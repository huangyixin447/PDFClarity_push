# M5 具体实现方案：桌面化（pywebview 壳 + 完整打包分发）

> 版本：v1.0 ｜ 前置：M0~M2 已完成；M3/M4 的界面二需求已按用户要求重构为「单一选择页 + 状态控制台」。
> 本文档先写方案（含风险与 bug 审查），审查通过后实施。

## 1. 目标与范围

把当前「FastAPI + Web 前端」变为**真正的桌面软件**：

| # | 子目标 | 说明 |
| ---- | ---- | ---- |
| G1 | pywebview 桌面壳 | uvicorn 与 pywebview 同进程；`python app.py` 打开原生窗口（WebView2） |
| G2 | 原生文件选择 | 桌面模式点选走原生对话框（返回绝对路径，原位引用不复制）；拖拽取绝对路径 |
| G3 | 数据目录迁移 | 打包态 `work/`、`output/` 落到持久目录，避免写入 `_MEIPASS` 临时目录被清空 |
| G4 | 端口处理 | 8000 被占用自动顺延；前端用相对路径 `/api`，无需注入端口 |
| G5 | 关闭处理 | 运行中关闭窗口 → 先请求取消并等子进程终止，避免孤儿进程 |
| G6 | 完整打包 | PyInstaller 打包 `ui/dist` + `bin/realesrgan` + `scripts` + pywebview，产物可真实超分 |

**本轮明确不做**（降低风险，后续跟进）：单实例互斥锁、原生菜单、自动更新。

## 2. 技术决策（已核实环境）

| 项 | 决策 | 依据（实测） |
| ---- | ---- | ---- |
| pywebview | 6.2.1（装于 `vendor/`） | `python -m pip install --target vendor pywebview` 成功；沙箱禁止写系统 site-packages |
| pythonnet | 3.1.0（装于 `vendor/`） | 3.14 需要 ≥3.1.0；`import clr` 通过 |
| WebView2 Runtime | 系统自带 | 本机已装 151.0.4129.107 |
| 拖拽取路径 | pywebview DOM drop（`pywebviewFullPath`） | 源码 `webview/util.py:298` 确认 4.3+ 特性在 6.2.1 保留；需注册 `document.events.drop` 触发原生拦截（`dom/element.py:413`） |
| 关闭拦截 | `window.events.closing`（`Event(window, True)` 同步执行） | `webview/event.py:63`：任一处理器返回 `False` → 阻止关闭 |
| 后端同进程 | uvicorn 跑非主线程（daemon） | 需覆写 `install_signal_handlers` 避免信号冲突 |

## 3. 实施方案（分步）

### 3.1 `core/paths.py`：冻结态数据目录迁移

- 新增 `_runtime_base()`：`sys.frozen` 为真时返回 `%LOCALAPPDATA%\PDFClarity`（无则 `~`），开发态返回项目根 `HERE`。
- `WORK_ROOT` / `OUT_ROOT` 改用 `_runtime_base()`；`ENGINE_EXE` / `MODEL_DIR` / `EXTRACT` / `REBUILD` / `_UI_DIST` 仍用 `HERE`（打包后即 `_MEIPASS`，指向随包资源）。
- 影响面：`server/files.py`（INBOX=work/inbox）自动跟随；CLI 非 frozen 行为零变化。

### 3.2 `server/bridge.py`（新增）：pywebview js_api 桥 + 关闭/拖拽钩子

- `class DesktopBridge`：`select_file()`（`webview.FileDialog.OPEN` + `*.pdf` 过滤，返回绝对路径或 None）、`open_in_folder(path)`（`os.startfile` 打开目录）。
- `setup_closing_guard(window)`：`events.closing +=` 处理器——运行中则 `jobs.request_cancel` + 轮询等待（≤15s）后放行。
- `setup_drop_handler(window)`：`window.dom.document.events.drop +=` 处理器——取 `dataTransfer.files[].pywebviewFullPath`，经 `evaluate_js("window.__pdfclarityDesktopPick(...)")` 通知前端选中。

### 3.3 `app.py`：桌面入口

- 保留 `uvicorn.run` 但改为线程内 `_UvicornThread(uvicorn.Server)`（屏蔽信号处理器）。
- `_find_free_port()`：8000 起顺延 20 个，再退化为系统随机端口。
- 启动 uvicorn → `webview.create_window("PDFClarity", f"http://127.0.0.1:{port}", js_api=bridge, width=1280, height=800, min_size=(960,640))` → 挂载 closing/drop 钩子 → `webview.start()`。
- pywebview 导入失败 → 回退 `webbrowser.open` + 主线程驻留（打印端口）。
- 新增 `--server-only` 参数：仅起服务不开窗口（浏览器模式，回归 M0~M4 行为）。

### 3.4 前端：桌面模式适配（`SelectPage.vue` / 新增小模块）

- 检测：`const isDesktop = !!window.pywebview?.api`。
- 桌面模式：`el-upload` 换成自定义 dropzone div（`@click` → `window.pywebview.api.select_file()` → `control.selectByPath`）；拖拽由 Python 侧 DOM 钩子回传路径。
- 全局定义 `window.__pdfclarityDesktopPick(path)` → `control.selectByPath(path)`。
- 完成后（`phase==='done'` 且有 `output_path`）桌面模式显示「在文件夹中显示」按钮（走 `open_in_folder`）。
- 浏览器模式：维持现状（el-upload 上传）。

### 3.5 `_stage_deps.py`：补齐 pywebview 依赖

- PACKAGES 追加：`webview/bottle/proxy_tools/clr_loader/cffi/pycparser/pythonnet`（pythonnet 含 `Python.Runtime.dll` 等原生程序集，整包复制）。

### 3.6 完整打包（PyInstaller）

```
python _stage_deps.py
$env:PYTHONPATH="D:\Code\PDFClarity_push\build\_stage;D:\Code\PDFClarity_push\vendor;D:\Code\PDFClarity_push\vendor_tools"
python -S -m PyInstaller --noconfirm --clean --onefile -n PDFClarity `
  --add-data "ui/dist;ui/dist" --add-data "bin/realesrgan;bin/realesrgan" --add-data "scripts;scripts" `
  --hidden-import webview.platforms.edgechromium --hidden-import clr_loader.windows `
  --collect-all pythonnet app.py
```

## 4. 风险与 bug 审查

| # | 风险 / 潜在 bug | 影响 | 对策 / 处置 |
| ---- | ---- | ---- | ---- |
| R1 | **拖拽路径依赖 DOM 监听器注册**（`num_listeners>0` 才触发原生拦截）；若本版本失效，拖拽退化为上传或无效 | 中 | 兜底：`__pdfclarityDesktopPick` 未定义时忽略；手动测试确认；必要时降级为浏览器上传路径 |
| R2 | **el-upload 与 pywebview 原生拖拽冲突**：注册 document drop 后，拖到上传区可能不再走 el-upload | 中 | 桌面模式已整体替换为自定义 div，无 el-upload 冲突面 |
| R3 | **PyInstaller + pythonnet/clr_loader**：平台模块为动态加载，漏收集即运行时报错 | 高 | 显式 `--hidden-import` + `--collect-all pythonnet`；打包后先 `import webview/clr` 冒烟再开窗 |
| R4 | **关闭语义**：`closing.set()` 任一处理器返回 `False` 才阻止关闭；处理器返回 `True` 会放行 | 低 | 钩子返回 `True`（放行），并先完成取消等待（`should_lock=True` 保证同步执行） |
| R5 | **paths 迁移影响**：frozen 下 `bin/scripts/ui` 仍取 `HERE(_MEIPASS)`，仅 work/output 迁移 | 低 | 分两类路径常量，不混用；CLI 非 frozen 不变 |
| R6 | **端口顺延**：前端 `client.js` 用相对 `/api` | 低 | 无注入需求；`--server-only` 回归 M0~M4 |
| R7 | **`webview.FileDialog.OPEN` 常量**（6.x 弃用 `webview.OPEN_DIALOG`） | 低 | 已核实 6.x 使用 `FileDialog.OPEN` |
| R8 | **pythonnet 打包体积**（含 .NET 程序集） | 低 | onefile 体积增大属预期；冒烟后评估是否改 onedir |
| R9 | **打包产物安全/误报** | 低 | 沿用 README「解除锁定」说明 |

## 5. 手动测试清单（用户执行）

1. `python app.py` → 弹出原生窗口（标题 PDFClarity），无控制台浏览器；端口被占时自动换端口仍可打开。
2. 桌面模式点选 → 原生文件对话框；选中后右侧显示文件信息；拖拽 PDF 到窗口 → 自动选中（路径模式，不复制）。
3. 跑一个真实任务：状态控制台逐行输出、进度条平滑、完成后「在文件夹中显示」可打开 output 目录。
4. 运行中关闭窗口 → 自动取消任务，进程退出后无残留 realesrgan/extract 进程（任务管理器确认）。
5. `python app.py --server-only` → 自动打开默认浏览器访问，浏览器模式上传仍可用。
6. `dist\PDFClarity.exe`：双击启动 → 出窗口 → 真实超分一个 PDF → output 落在 `%LOCALAPPDATA%\PDFClarity\output`。

## 7. 实施偏差记录（实施后补写）

| # | 方案原文 | 实际实施 / 发现 | 原因与影响 |
| ---- | ---- | ---- | ---- |
| D1 | `_wait_until_up` 超时 15s | 改为 60s | `jobs.init()` 的 self_check 同步跑一次引擎 GPU 探测（`probe_gpus`，上限 120s）。实测沙箱下需 **24.5s**，15s 会误判启动失败。正常环境数秒即可。 |
| D2 | 3.5 依赖从 site-packages 复制 | pywebview/pythonnet 装在 `vendor/`，`_stage_deps.py` 改为同时从 `vendor/` 复制（新增 `VENDOR_ITEMS`/`VENDOR_META`，区分文件与目录） | `pip install --target vendor` 的包不在 Anaconda site-packages；`python -S` 隔离打包必须显式带上。 |
| D3 | 打包产物体积 | `dist/PDFClarity.exe` = **91.8MB**（onefile） | pythonnet `runtime/*.dll`（约 150 个 .NET Standard 程序集）+ 引擎 bin/ + 前端 dist。属预期，可后续评估改 onedir。 |
| D4 | 拖拽/关窗钩子 | 已按方案实现并经 `vendor/webview` 源码逐条核实（`Element.on` 的 `num_listeners` 计数、`closing.set()` 同步执行语义、`pywebviewEventHandler` 的 drop 分支回填 `pywebviewFullPath`） | 无偏差。 |
| D5 | 端口顺延 | 冒烟实测：8000 被占时 uvicorn 落在 **8001**，前端相对路径 `/api` 正常工作 | 无偏差。 |
| D6 | 冒烟结论（沙箱内） | exe 桌面模式启动成功：进程存活、`Application startup complete`、WebView2 无崩溃 | 沙箱限制 `nvidia-smi`/WebView2 写用户目录会打沙箱警告，但主流程不受影响；完整交互留待用户手动测试。 |
| D7 | onefile 进程模型 | Windows onefile = bootloader 父进程 + 应用子进程；强杀父进程会残留子进程（uvicorn 仍监听端口） | 正常关窗口 → 子进程退出 → 父进程随之退出，无残留；仅任务管理器强杀才可能残留。 |
