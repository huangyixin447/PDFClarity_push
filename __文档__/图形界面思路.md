## 1. 背景与目标

### 1.1 现状

PDFClarity 目前是纯命令行工具，入口为 `python run.py <输入.pdf|文件夹> [放大倍数] [目标宽度]`，内部为三段式流水线：

```
[1/3] scripts/extract_pages.py    PDF → 每页 PNG（顺带修复 JPEG2000 空白问题）
[2/3] bin/realesrgan/…-vulkan     Real-ESRGAN AI 超分（GPU/Vulkan）
[3/3] scripts/rebuild_pdf.py      超分后的 PNG → 干净 PDF
```

`run.py` 中已具备可复用的核心逻辑：GPU 自动枚举与选择（`probe_gpus` / `pick_gpu`）、实时系统监控（`SysMonitor`，nvidia-smi + psutil 双来源）、阶段进度轮询（`count_png` / `count_tmp_jpg`）、页数探测（`pdf_page_count`）。每段流水线都会产出 `extract.log` / `upscale.log` / `rebuild.log`，目前**需要用户手动打开查看**。

### 1.2 为什么需要 GUI

- 命令行参数（MODEL、GPU_IDS、EXTRA_ARGS、EXTRACT_WORKERS 等）对非技术用户门槛高；
- 处理长文档（实测 173 页 PDF）时，用户希望实时看到「正在处理哪一页、每页进度」；
- 需要一个直观闭环：**选文件 → 调参数 → 点开始 → 看进度与日志 → 打开成品**，不必再去文件管理器里翻 log。

### 1.3 目标（本次范围）

1. 选择文档界面：点击或拖拽选择 PDF；
2. 工作界面：左侧缩略图导航（页级进度可视化）+ 右侧**常驻日志面板**（取代手动打开 log 文件）；
3. 常驻侧边栏：CPU / GPU 等系统指标 + 全部可调参数；
4. 「开始超分」按钮与运行状态机；
5. 底部进度条 + 可取消。

### 1.4 非目标（明确不做）

- 在线 / 云端超分服务；
- 大图预览（单击缩放 / 平移 / 原图对比）—— 已裁剪，留出的位置给日志面板；
- WebSocket / SSE 等长连接实时推送 —— 本轮取舍为 **HTTP 轮询**；
- 除 PDF 外的输入（图片批量超分、多文件队列）—— 列为后续扩展；
- 移动端。

### 1.5 延迟取舍（本轮关键决策）

**放弃 <0.5s 的实时性，接受 0.5~1s 的界面刷新延迟**，换取显著降低实现难度：

- 砍掉 WebSocket：后端不再维护长连接、连接管理、断线重连、心跳；
- 砍掉线程 ↔ asyncio 事件桥：后台线程把进度 / 日志 / 监控数据**直接写入内存全局字典**（加锁），前端定时轮询读取即可；
- 代价仅是进度条、日志、系统指标最多慢 1s 刷新，对超分任务（单页耗时秒级、总耗时分钟级）完全可接受。

## 2. 技术选型（已定稿）

### 2.1 技术栈明细

**决策：Python 后端 + Web 前端，用 pywebview 包成桌面窗口，前后端通信全部走 HTTP 轮询。**

| 层 | 技术 | 版本建议 | 选型理由 |
| ---- | ---- | ---- | ---- |
| 桌面壳 | pywebview | ≥ 5.0 | 原生窗口内嵌 Edge WebView2（Windows）；5.0+ 支持文件拖拽回传绝对路径（`pywebviewFullPath`，Python 侧经 DOM `DropEvent` 获取，已核实）；支持原生文件对话框（`create_file_dialog`）；打包体积远小于 Electron。⚠️ Windows 后端依赖 pythonnet，**Python 3.14 需 pythonnet ≥ 3.1.0**（见第 9 节风险 7） |
| 后端框架 | FastAPI + Uvicorn | FastAPI ≥ 0.110 | 异步框架；本地服务即开即用；自带 OpenAPI 便于调试；仅需同步接口，无 WS 复杂度 |
| 前后端通信 | **HTTP 轮询** | REST | 每 0.5~1s 轮询 `GET /api/state` 与 `GET /api/logs`；无长连接、无事件桥，实现最简 |
| 前端框架 | Vue 3 + Vite | Vue ≥ 3.4 | SPA 开发体验好，组件化符合本界面结构；Vite 构建快 |
| UI 组件库 | Element Plus | 最新稳定 | 表单、进度条、消息提示、对话框等现成组件，中文生态完善 |
| 状态管理 | Pinia | 最新稳定 | 管理全局状态机（IDLE/READY/RUNNING…） |
| 核心逻辑 | 复用 `run.py`（抽取为 `core/` 模块） | — | 提取 / 超分 / 重建与监控逻辑已验证，CLI 与 GUI 共用同一份代码 |
| 打包 | PyInstaller | 最新稳定 | 打包 app.py + 后端 + 前端 dist + bin/ + scripts/ |

> 备选说明：若完全不需要「桌面感」，可直接去掉 pywebview，让用户用浏览器访问 `http://127.0.0.1:8000`，前端代码零改动（仅文件选择与拖拽走「上传」降级路径，见 2.4）。

### 2.2 系统架构

```
┌───────────────────────────────────────────────────────────┐
│  前端（Vue3 + Vite + Element Plus，跑在 pywebview 窗口内）    │
│  · 界面一：选择文档     · 界面二：工作界面（缩略图 + 日志）      │
│  · 侧边栏（参数 + 系统监控）· 底部进度                        │
└──────────────┬────────────────────────────────────────────┘
               │ HTTP 轮询（0.5~1s）：GET /api/state、/api/logs
               │ REST（启动/取消/查询/取图）+ pywebview 原生桥
┌──────────────▼────────────────────────────────────────────┐
│  后端（FastAPI + Uvicorn，本地 127.0.0.1 服务）               │
│  · main.py      应用装配、路由、静态托管                       │
│  · jobs.py      任务调度：后台线程 + 全局状态字典 + 取消        │
│  · api_media.py 缩略图 / 日志增量接口                        │
│  · select       pywebview 桥（原生对话框 / 拖拽路径）          │
└──────────────┬────────────────────────────────────────────┘
               │ 进程内调用（任务线程，只写共享字典）
┌──────────────▼────────────────────────────────────────────┐
│  任务层（core/ 模块，抽取自 run.py，CLI 与 GUI 共用）           │
│  · pipeline.py  process_one() 进度/日志回写版                │
│  · monitor.py  SysMonitor（nvidia-smi + psutil）            │
│  · gpu.py      probe_gpus / pick_gpu                       │
│  · progress.py count_png / count_tmp_jpg / pdf_page_count  │
└──────────────┬────────────────────────────────────────────┘
               │ subprocess
┌──────────────▼────────────────────────────────────────────┐
│  引擎层（保持不变）                                          │
│  · extract_pages.py · realesrgan-ncnn-vulkan · rebuild_pdf.py │
└───────────────────────────────────────────────────────────┘
```

关键设计：

1. **前后端同进程部署**：uvicorn 与 pywebview 在同一 Python 进程内启动；pywebview 的 `js_api` 桥直接调用后端函数（选文件、取消），REST 只负责资源接口（取图、日志）；
2. **任务异步化（简化版）**：流水线是阻塞式 subprocess，放到**后台线程**运行；线程把进度 / 日志 / 系统指标**写入进程内全局字典**（`threading.Lock` 保护），**不经过事件循环、不维护任何长连接**；
3. **前端轮询**：一个统一定时器（0.5~1s）拉取 `GET /api/state`（进度 + 系统指标）与 `GET /api/logs?offset=`（日志增量），更新 Pinia store；
4. **CLI 不破坏**：`run.py` 保留为薄封装，import `core/` 后行为与现状完全一致（含终端状态栏），回归成本低。

### 2.4 文件选择 / 拖拽的三种通道

| 场景 | 通道 | 是否落盘 |
| ---- | ---- | ---- |
| 点击选择（桌面壳） | pywebview `create_file_dialog` → 返回本地绝对路径 → 直接交给后端 | 否（原位引用） |
| 拖拽（桌面壳，pywebview 5.0+） | Python 侧订阅 DOM `drop` 事件（`DOMEventHandler`），取 `event.dataTransfer.files[].pywebviewFullPath`（5.0+ 提供，Python 侧可读） | 否（原位引用） |
| 纯浏览器模式（开发/备选） | `<input type=file>` / 拖拽 File → multipart 上传到 `inbox/` 临时目录 | 是（复制一份） |

> 三种通道前端统一为「拿到一个文件标识（路径或已上传的文件 id）」，调用同一套「选中文件 → 探测信息 → READY」逻辑，避免分支发散。

### 2.5 后端接口一览（全部为 HTTP，无长连接）

**轮询约定**：前端用一个统一定时器，`GET /api/state` 与 `GET /api/logs` 以 0.5~1s 周期并发拉取；仅当存在活动任务或界面可见时轮询，空闲 / 页面隐藏时暂停，减少无效请求。

| 方法 / 路径 | 说明 |
| ---- | ---- |
| `GET /api/state` | **轮询主接口**：任务阶段、页码、总页数、运行中标志、系统指标（GPU/CPU/内存快照）、GPU 列表、引擎可用性 |
| `POST /api/jobs` | 创建任务（参数：文件路径、scale、target_width、model、gpu_ids、workers、skip_existing），返回 job_id |
| `POST /api/jobs/{id}/cancel` | 取消任务（终止子进程 + 清理临时文件） |
| `GET /api/jobs/{id}` | 查询任务详情（含失败信息） |
| `GET /api/files/inspect?path=` | **选中文件探测（界面一必需，原接口表遗漏）**：校验扩展名 / 存在性，返回文件大小与 `pdf_page_count` 页数（失败返回 null）；补齐「选中文件 → 探测信息 → READY」链路 |
| `GET /api/thumbs/{id}/{page}` | 缩略图（按需生成，`work/<base>/src/` 来源，服务端落盘缓存；缓存键需叠加源图 mtime，避免同书重跑显示旧图） |
| `GET /api/logs?offset=N&file=extract` | **轮询日志**：按字节偏移返回该日志文件的新增内容 `{lines, next_offset}`；前端保存 `next_offset` 作为下次请求的 `offset`；**阶段切换或新一轮任务时对应文件的 `offset` 归零**（各日志文件游标相互独立） |

> 系统指标不再每秒推送：`SysMonitor` 后台线程仍然常驻采样，把最新值写入全局字典；`GET /api/state` 读取的是**最近一次采样快照**，延迟 ≤ 1 个采样周期。

## 3. 界面设计

### 3.1 总体布局

```
┌────────────────────────────────────────────────────────┐
│ 顶栏（应用标题 + 当前文件显示）                             │
├──────────────┬─────────────────────────────────────────┤
│              │  界面一：选择文档                          │
│   侧边栏      │  ┌──────────────────────────────┐        │
│  (始终不变)   │  │  大拖放框                      │        │
│  · 系统监控    │  │  点击选择 / 拖入 PDF 文件       │        │
│  · 参数调节    │  │  选中后显示：文件名 · 页数       │        │
│  · 开始超分    │  └──────────────────────────────┘        │
│              ├─────────────────────────────────────────┤
│              │  界面二：工作界面                          │
│              │  ┌──────────┬───────────────────────┐    │
│              │  │ 缩略图列表 │  日志面板（常驻主区域）  │    │
│              │  │ (懒加载)  │  近实时跟随 + 回看     │    │
│              │  │ 页级进度  │  阶段自动切换          │    │
│              │  └──────────┴───────────────────────┘    │
├──────────────┴─────────────────────────────────────────┤
│ 底部状态条（仅界面二）：阶段 | 进度条 | 用时 | 取消          │
└────────────────────────────────────────────────────────┘
```

- 侧边栏固定宽度（约 280px），两界面共用、始终可见；
- 右侧主区域用 `v-if` / 路由切换界面一 / 界面二；
- 底部状态条在界面二显示；界面一不占空间。

### 3.2 界面一：选择文档界面

- 主体为**大拖放框**：
  - **点击**：桌面壳走 pywebview 原生对话框（过滤 `*.pdf`）；浏览器模式走 `<input type=file>`；
  - **拖拽**：仅接受**单个 `.pdf`**；拖入文件夹 / 多文件时提示「仅支持单个 PDF」并忽略；
  - 选中后框内显示：文件名、文件大小、页数（`pdf_page_count` 探测，失败显示「未知」）；
  - 支持再次点击 / 拖入重新选择；
- 选中文件后，侧边栏「开始超分」按钮点亮。

### 3.3 界面二：工作界面

本界面裁剪了大图预览，将空出的位置交给**常驻日志面板**，用户无需再手动打开 `work/<书名>/*.log`。

- **左侧缩略图列表**（`ThumbList.vue`）：
  - 数据源：`work/<书名>/src/page_NNNN.png`；提取完成前该页显示占位符；
  - 长列表性能：**懒加载（`loading="lazy"` + 可视窗口渲染即可）**，虚拟滚动为可选项；缩略图由后端接口按需生成并缓存；
  - 承担**页级进度可视化**：处理中自动高亮「正在处理的页」并滚动定位；
  - 点击缩略图可手动浏览并高亮任意页（用于对照日志中提到的页码），不影响任务。
- **右侧日志面板**（`LogPanel.vue`，常驻）：
  - 通过轮询 `GET /api/logs?offset=` 获取增量，展示 `extract.log` / `upscale.log` / `rebuild.log` 的完整内容（含「哪一秒完成了哪一项」），按阶段自动切换文件；
  - **自动跟随**：默认贴底滚动，跟随最新输出（延迟 ≤ 1s）；
  - **回看**：用户向上滚动时暂停自动跟随，滚回底部后恢复；
  - 新一轮任务开始时清空面板、前端 `offset` 归零；
  - 日志量过大时限制渲染行数（只保留可视窗口），避免长任务卡顿。

### 3.4 侧边栏（两界面共用，自上而下）

1. **系统监控区**：
   - GPU：占用率进度条、显存占用、温度、功耗（nvidia-smi；AMD / 集显显示 n/a）；
   - CPU 占用率、内存占用（psutil）；
   - 数据随 `GET /api/state` 轮询刷新（0.5~1s），展示最近采样快照；
2. **参数调节区**（默认值对齐现有 CLI）：

   | 参数 | 默认 | 控件 | 对应 CLI 项 | 校验 |
   | ---- | ---- | ---- | ---- | ---- |
   | 放大倍数 | 4 | 下拉框 | `scale` | ∈ {2, 4} |
   | 目标宽度 | 4320 | 数值框 | `target_width` | 0 或正整数（0 = 保留完整尺寸） |
   | 超分模型 | realesrgan-x4plus | 下拉框（含 -anime 等） | `MODEL` | 非空 |
   | GPU 编号 | 自动选择 | 下拉框（启动时枚举填充） | `GPU_IDS` | 探测失败显示「自动（回退 0）」 |
   | 提取并行进程数 | min(8, CPU 核数) | 数值框 | `EXTRACT_WORKERS` | [1, CPU 核数] |
   | 跳过已有成品 | 开 | 勾选框 | `SKIP_EXISTING` | — |

   **开始工作后整个参数区变灰禁用**，防止运行中改动导致结果不一致；参数校验不通过时禁用「开始」并提示。
3. **开始超分按钮**：
   - 未选择文件 / 参数非法：禁用；
   - 已就绪且空闲：**开始超分**（高亮可点）；
   - 运行中：变为 **正在超分…**，禁用点击；
   - 结束后恢复可点，可继续处理下一个文件。

### 3.5 底部状态条（仅界面二）

- 实时显示：当前阶段（提取 / 超分 / 重建）+ 页码与百分比 + 阶段用时；
- 进度数据来源（与 CLI 一致，不依赖解析引擎输出，经 `/api/state` 轮询）：
  - 提取：`count_png(work/<书名>/src)`；超分：`count_png(work/<书名>/up)`；重建：`count_tmp_jpg(output)`；
  - 页数探测失败时进度条退化为「页码推进」，百分比显示 `--`；
- **取消按钮**：运行中可用，点击弹确认后取消（见 5.3）；空闲时禁用；
- 完成后显示成品路径与**「打开所在文件夹」**按钮。

### 3.6 交互细节汇总

| 交互 | 行为 |
| ---- | ---- |
| 点击拖放框 | 打开系统文件选择器（仅 PDF） |
| 拖入单个 PDF | 选中文件 |
| 拖入文件夹 / 多个文件 | 提示「仅支持单个 PDF」并忽略 |
| 点击左侧缩略图 | 高亮定位该页（对照日志页码） |
| 日志面板自动滚动 | 跟随最新输出（轮询，≤1s 延迟） |
| 日志面板向上滚动 | 暂停自动跟随（回看） |
| 日志面板滚回底部 | 恢复自动跟随 |
| 点击「取消」 | 弹确认 → 终止任务并清理临时文件 |
| 任务运行中修改参数 | 参数区灰底禁用 |
| 任务运行中点击开始 | 按钮禁用，防重入 |
| 任务失败 | 状态区提示 + 日志定位 + 「重试」按钮 |
| 单页处理失败 | 日志标记该页并继续后续（与 CLI 一致） |

## 4. 各界面/模块难度评估

### 4.1 评估口径

按「实现工作量 + 交互复杂度 + 需要自研的技术点」三方面打分，分为**低 / 中 / 高**三档。低：有成熟组件或可直接复用现有逻辑；中：有性能或状态细节需要专门处理；高：需要自研机制或跨层协作。

### 4.2 评估表

| # | 界面 / 模块 | 难度 | 关键理由与技术点 |
| ---- | ---- | ---- | ---- |
| 1 | 选择文档界面（点击 / 拖拽 / 文件信息） | **低** | pywebview 原生对话框 + 5.0+ 拖拽回传绝对路径；浏览器模式降级为上传；页数探测复用 `pdf_page_count`；无自研组件 |
| 2 | 侧边栏 · 系统监控区 | **低** | 后端 `SysMonitor` 原样复用（后台线程写全局字典）；随 `/api/state` 轮询渲染；注意 AMD / 集显的 n/a 兜底显示 |
| 3 | 侧边栏 · 参数调节区 | **低** | Element Plus 表单组件；校验 + 运行中禁用的状态联动；无性能问题 |
| 4 | 开始 / 取消按钮 + 状态机 | **低** | Pinia 状态机驱动按钮三态与防重入；与后端 job 状态单向同步 |
| 5 | 底部进度条 | **低** | `/api/state` 轮询 → Element Plus 进度条；页数未知时退化为页码显示 |
| 6 | 工作界面 · 缩略图列表 | **中** | 173 页长列表：**懒加载 + 可视窗口渲染即可，虚拟滚动降为可选项**（120px 缩略图数十项开销可忽略）；主要工作量移到后端：按需生成缩略图 + 落盘缓存 + **缓存失效处理（同书重跑需按源图 mtime 校验或任务开始时清空）**；当前页高亮 + 滚动跟随 |
| 7 | 工作界面 · 日志面板（常驻主区域） | **中** | 轮询增量读取（offset 断点）+ 自动跟随 / 上滚暂停 / 贴底恢复 + 大日志渲染限行；阶段切换时切换日志文件；游标重置 |
| 8 | 后端任务调度 | **中** | 已砍掉事件桥与长连接，难度回落；仅剩全局字典 + 锁 + 取消，拆解见 4.3 |
| 9 | 打包分发（pywebview + uvicorn + 前端 dist + bin/） | **中** | PyInstaller 打多资源目录（`--add-data`）；uvicorn 端口占用冲突处理；杀软误报说明；前端 dist 需随包分发 |

### 4.3 后端任务调度难度拆解

砍掉 WebSocket 与线程 ↔ asyncio 事件桥后，后端调度**不再有「高」难度子模块**，整体由「高」降为「中」：

| 子模块 | 难度 | 难点分析 | 缓解措施 |
| ---- | ---- | ---- | ---- |
| S1. `run.py` → `core/` 重构（保持 CLI 回归） | 中 | 代码搬移的回归风险；run.py 依赖模块级常量（路径）与全局判断（IS_TTY） | 分步搬移、每次跑一遍 CLI 冒烟（1 个 2 页 PDF 对照输出）；常量保留为模块级并显式传入；**兜底降险**：若回归不可控，可暂缓拆分，GUI 直接 `import run` 复用现有函数（同进程内共享模块级常量天然可用） |
| S2. `process_one` 进度 / 日志回写 | 低 | **无需改 `process_one` 签名**：`run_with_progress` 每 0.4s 调用一次 `bar.render(stage, cur, total, t0, metrics)`，GUI 传入一个与 CLI `StatusBar` 同协议（render / newline）的自定义 bar 对象即可，由它把 stage/cur/total 写入全局字典——`bar.render` 本身就是现成的进度回调；日志本就写文件、由前端按 offset 轮询读取；成败由 `process_one` 返回值判定 | 唯一必要的代码改动是暴露当前 `proc` 句柄供取消（见 S4）；CLI 仍传原 `StatusBar`，行为零影响 |
| S3. 全局状态字典 + 锁 | 低-中 | 唯一的并发点是「写线程 vs 读请求」，比事件桥简单一个数量级 | 单个 `threading.Lock` 保护字典；读接口 `deepcopy` 或整字典快照后返回，避免半写状态 |
| S4. 取消与子进程终止 | 中 | Windows 下 `terminate()` 只杀主进程、子进程树可能残留；终止时序与临时目录清理存在竞态 | 持有当前 `proc` 句柄；`terminate()` 后超时强杀（`taskkill /T` 杀进程树）；清理放 `try/finally` 且幂等；取消后状态置 READY 保证可重入 |
| S5. 任务状态机与防重入 | 中 | 前端 Pinia 与后端全局字典双份状态的一致性 | 后端为唯一事实源；`/api/state` 每次轮询都会带回完整快照，前端整体覆盖 |
| S6. 日志增量读取与游标 | 低-中 | `offset` 游标由前端持有；新任务时日志文件被清空重写，游标需重置；**阶段切换时换文件、跨文件游标无效** | 后端返回 `next_offset`；前端在新任务开始时归零；**切换日志文件时对该文件独立归零**；渲染节流 |
| S7. 自检与 GPU 枚举 | 低 | 现成逻辑搬移即可 | — |

**结论**：取消 WS 后，原先唯一的「高」来源（线程 ↔ asyncio 事件桥）被整体移除，替换为「全局字典 + 锁」这一低-中难度机制；剩余最高难度为**中**（S1 重构回归、S4 取消）。后端调度已不再是项目的风险重心。

### 4.4 难度汇总与排序

- 总体难度由上一版的「中等」进一步降为**中等偏低**，**已无「高」难度模块**；
- 现有 4 个「中」：缩略图列表（6，重点为后端按需生成 + 缓存失效）、日志面板（7）、后端调度（8）、打包（9）——均为常规工程问题，无自研高风险机制；
- 低难度模块（1~5）合计占比最大，**建议先行**，可快速得到可用骨架；
- 依赖关系：模块 1~7 全部依赖模块 8 提供的「任务调度 + 全局状态」能力，因此 **8 仍须最先落地（M0/M1）**，详见第 10 节里程碑。

## 5. 状态机与数据流

### 5.1 全局状态

```
IDLE(未选文件) ──选中文件──▶ READY(待开始)
READY ──点击开始──▶ RUNNING(提取 → 超分 → 重建)
RUNNING ──完成──▶ DONE(展示成品入口)
RUNNING ──取消──▶ IDLE/READY(保留当前文件)
RUNNING ──失败──▶ ERROR(日志定位) ──重试──▶ RUNNING
DONE / ERROR ──重新选择文件──▶ READY
```

- 状态由前端 Pinia 持有，以后端全局字典（经 `/api/state`）为准，前端刷新 / 轮询恢复后自动同步；
- **重试**：ERROR 状态下「重试」用当前参数重新创建任务（等价于重新点击开始）。

### 5.2 运行流程

1. 应用启动：后端自检（引擎存在性、`probe_gpus` 枚举、nvidia-smi 可用性）→ 结果写入全局字典 → 前端启动轮询器，首次 `GET /api/state` 初始化界面；
2. 用户选择文件 → `pdf_page_count` 探测页数 → READY；
3. 点击开始 → `POST /api/jobs` → 后台线程依次执行提取 / 超分 / 重建（复用 `core.pipeline.process_one`，回调写全局字典）；
4. 每段进度由 `count_png` / `count_tmp_jpg` 轮询（约 0.5s）写入字典 → 前端轮询 `/api/state` 驱动进度条、缩略图高亮跟随；
5. 日志由前端轮询 `GET /api/logs?offset=` 增量拉取 → 日志面板跟随滚动；每段切换日志文件（extract → upscale → rebuild）；
6. 全部完成 → 字典标记 done → 前端显示成品入口与「打开所在文件夹」。

### 5.3 取消 / 中断 / 异常

- **取消**：`POST /api/jobs/{id}/cancel` → 设置任务停止标志 → 终止当前子进程（`proc.terminate()`，超时 `taskkill /T`）→ 清理 `output/_jpg_tmp_*` 临时目录 → 恢复 READY（保留当前选中文件）；
- **关闭窗口**：pywebview `confirm_close` 弹确认；确认关闭则终止任务与子进程后退出；
- **轮询中断 / 前端刷新**：HTTP 短连接无长连接可断；定时器失败自动重试（指数退避），刷新页面后下一次轮询即自动恢复界面状态，**无需任何重连逻辑**；
- **崩溃残留**：启动时检测 `work/` 下遗留中间文件，提示清理或忽略（重跑时任务内自动清空 src/up，与 CLI 一致）。

## 7. 关键实现要点

1. **`run.py` 重构为 `core/` 模块**：把 `main()` 之外的逻辑（`process_one`、`SysMonitor`、`probe_gpus`、`count_png` 等）抽入 `core/`；**进度回写不依赖新增回调**：GUI 传入与 CLI `StatusBar` 同协议的自定义 bar 对象即可，`run_with_progress` 每 0.4s 的 `bar.render(stage, cur, total, …)` 就是现成的进度通道；日志走文件轮询、成败看 `process_one` 返回值，CLI 行为零影响。**兜底**：若重构回归不可控，GUI 可暂缓拆分、直接 `import run` 复用现有函数；
2. **全局状态字典**：`server/jobs.py` 内维护 `STATE = {"job":…, "phase":…, "page":…, "total":…, "running":…, "metrics":{…}, "gpus":[…], "done":…, "error":…}`，用 `threading.Lock` 保护；任务线程只写、`/api/state` 只读（返回快照副本），全程无事件循环、无连接；
3. **轮询器（前端）**：Pinia store 内一个统一 `setInterval`（500ms~1s）并发拉取 `/api/state` 与 `/api/logs`；有活动任务或界面可见才轮询，空闲暂停；失败指数退避重试；
4. **缩略图按需生成**：`/api/thumbs/{id}/{page}` 首次请求时用 PIL 生成 120px 宽缩略图并落盘 `work/.thumbs/`，此后直接返回文件；缓存键叠加源图 mtime，同书重跑时自动失效（前端用 `loading="lazy"`，可视窗口渲染即可，无需虚拟滚动）;
5. **日志增量与自动跟随**：`/api/logs?offset=` 返回 `{lines, next_offset}`；前端默认贴底自动滚动，检测到用户向上滚动即暂停跟随，贴底恢复；渲染限行 + 节流；
6. **pywebview 桥**：`js_api` 暴露 `select_file()`（原生对话框）、`open_in_folder(path)`（打开所在目录）；拖拽路径在 Python 侧订阅 DOM `drop` 事件获取；
7. **单实例锁**：启动时尝试创建互斥（如独占 socket / 文件锁），已运行时提示并退出。

## 9. 风险与注意事项

1. **不要重写流水线**：提取 / 超分 / 重建已做大量性能与兼容性调优，GUI 只做壳；`core/` 抽取必须保证 CLI 行为不回归；
2. **全局字典并发**：唯一的并发点是「写线程 vs 读请求」，务必用锁保护并对读返回快照副本；`metrics` 采样由 `SysMonitor` 线程独立写入，与任务线程不冲突；
3. **轮询频率与负载**：0.5~1s 轮询对本地服务负载可忽略，但需**单一定时器**统一调度，避免多个组件各自轮询；空闲 / 页面隐藏时暂停；
4. **端口冲突**：固定端口被占时自动顺延，并把实际端口注入前端；
5. **磁盘压力**：4x 中间 PNG 较大，机械盘并发写盘可能抖动，参数区保留 EXTRACT_WORKERS 可调；
6. **pywebview 版本**：拖拽绝对路径依赖 5.0+，锁版本；非 Windows（macOS）拖拽行为需回归验证。
7. **Python 版本与环境一致性**：本机实际为 Python 3.14（`environment.yml` 仍声明 3.12，需统一）；pywebview 在 Windows 依赖 pythonnet，**3.14 需 pythonnet ≥ 3.1.0**（更早版本无 3.14 wheel），需锁版本并做最小冒烟（建窗口 + 原生对话框 + 拖拽取绝对路径）。
8. **缩略图缓存失效**：`work/.thumbs/` 若只按页码缓存，同书重跑（重新提取）后会显示旧图；缓存键叠加源图 mtime / 尺寸，或任务开始时清空该书缓存。
9. **打包风险后置**：PyInstaller 对 uvicorn（隐藏导入）与 pywebview（win32 平台模块）的收集问题往往到 M5 才暴露；建议 **M1/M2 收尾各做一次最小 exe 冒烟**（uvicorn + 静态页 / 全流程骨架），提前消化打包类风险。
