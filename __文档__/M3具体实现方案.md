## 0. 目标、需求与验收

### 0.1 本轮需求（用户 2026-08-19 原话要点）

1. **砍掉缩略图列表**：界面二不做缩略图导航，只显示**底部进度条**与**日志面板**；
2. **整体界面布局不变**：顶栏、常驻侧边栏、主区域框架与 M2 保持一致；
3. **进度条（心理安慰为主）**：正常条状进度条，**中间文字 `xx% : [项目类型] 具体工作`**（如 `45% : [提取] 正在提取第 12/173 页`）；并发时随便选一条写即可；
4. **日志（必须严格）**：可追溯——不丢行、可回看历史、任务间不串；**自动滚动规则：只有最后一条日志被显示（贴底）时才自动向下滚动，用户向上翻找即停止**；
5. **加权进度**：三大项目 **20% / 70% / 10%**，具体进度加权后换算成总百分比；
6. **用时 + 估算时间**：用时显示在**进度条上方**，旁边显示估算时间；**估算算法暂时留白，本轮只完成显示 UI，后续测试后写入**；
7. **取消按钮本轮完成**：运行中可取消任务（含后端终止子进程），并评估实现难度。

### 1.2 现状缺口（M3 必须处理）

1. **percent 是「阶段内」百分比**（[jobs.py](file:///d:/Code/PDFClarity_push/server/jobs.py#L123-L125)），阶段切换会回跳 → 需加权；
2. **message 无具体工作内容**（无页码/总数）→ 需增强；
3. **日志 2000 行环形截断**会丢最早行 → 与可追溯矛盾；
4. **只拉当前阶段日志**，切换 tab 历史不完整 → 改三文件全量轮询；
5. 无「界面二」组件与切换入口；
6. **无取消机制**：pipeline 的 `run_with_progress` 循环没有停止标志，`proc` 句柄不外传 → 需参数化 + 子进程树终止 + 状态机 + 路由（本轮新增，§3.4）。

### 1.3 关键设计决策

| # | 决策 | 理由 |
| ---- | ---- | ---- |
| D1 | **加权在后端算**（jobs.py `on_progress` 由 phase 定位权重），前端只消费 `state.percent` | STATE 是唯一事实源；phase 回调现成 |
| D2 | **message 后端增强**为 `[类型] 具体工作`，前端只拼 `xx% : message` | 内容来自真实 cur/total；并发天然取单条 |
| D3 | **日志三文件全量增量轮询** + 去 2000 行截断（50000 行异常兜底） | 任意 tab 实时 + 可追溯 |
| D4 | **底部区域两行**：上行 = 用时 + 估算时间（占位）+ 取消 + 更换文档；下行 = 进度条 | 用户指定用时在进度条上方、ETA 留白、取消本轮 |
| D5 | **取消用布尔标志而非 Event**：`STATE["cancel_requested"]` + 任务线程 0.4s 轮询检查 | 规避 `snapshot()` 深拷贝 threading.Event 崩溃；不引入额外字典 |
| D6 | **取消侵入 pipeline 但全可选参数**：`should_stop`/`on_cancel` 默认 None，CLI（run.py）零影响 | 保持 CLI/服务双入口兼容（M0 S1 回归约束） |
| D7 | **子进程树终止**：先 `terminate()`，3s 未退再 `taskkill /T /F` | Windows 下 `terminate()` 只杀主进程；extract_pages `--workers 8` 内部是进程池，必须杀树 |
| D8 | **取消后清理 `output/_jpg_tmp_*`**（幂等 glob+rmtree） | rebuild 中断会残留临时 jpg；src/up 中间页保留（重跑时 pipeline 开头自清） |
| D9 | 日志 tab 不做自动切换，当前阶段 tab 加小圆点 | 避免抢用户控制权 |
| D10 | **ETA 只做显示位**：`etaText` 占位 `--:--`，算法注释留白 | 用户要求：算法待真实任务数据测试后写入 |

```python
# —— M3 新增:三大项目加权(用户指定 20/70/10,进度条仅作心理安慰) ——
# 总进度 = 前序阶段已完成部分(_STAGE_BASE) + 本阶段权重(_STAGE_W) × 本阶段完成度
_STAGE_W = {"extract": 0.20, "upscale": 0.70, "rebuild": 0.10}
_STAGE_BASE = {"extract": 0.00, "upscale": 0.20, "rebuild": 0.90}
_STAGE_TAG = {"extract": "提取", "upscale": "超分", "rebuild": "重建"}


def _weighted_percent(phase, cur, total):
    """按 20/70/10 加权换算全局进度百分比(0~100)。total 探测失败按 0。"""
    w = _STAGE_W.get(phase, 0.0)
    base = _STAGE_BASE.get(phase, 0.0)
    frac = (cur / total) if total else 0.0
    return int(round((base + w * frac) * 100))


def _stage_message(phase, cur, total):
    """进度条中间文字: `[类型] 正在xxx第 cur/total 页`。
    多进程提取时 on_progress 由单线程轮询 count_fn 汇总推进(天然顺序覆盖,即「随便选一条」)。"""
    tag = _STAGE_TAG.get(phase, phase)
    if total:
        return f"[{tag}] 正在{tag}第 {cur}/{total} 页"
    return f"[{tag}] 正在{tag}…(页数未知,按推进估算)"
```

```python
def _job_thread(job_id, params):
    pdf = params["pdf"]

    def on_stage(phase, label):
        _update(phase=phase, stage_label=label,
                message=f"[{_STAGE_TAG.get(phase, label)}] 开始{_STAGE_TAG.get(phase, label)}…",
                error=None)

    def on_progress(phase, cur, total):
        _update(phase=phase, page=cur, total=total,
                percent=_weighted_percent(phase, cur, total),
                message=_stage_message(phase, cur, total))

    def on_done(ok, out_path, elapsed, per_page):
        _update(running=False,
                phase="done" if ok else "error",
                output_path=out_path,
                percent=100 if ok else STATE["percent"],   # done 满格/error 定格
                message="完成" if ok else "失败",
                error=None if ok else "阶段失败,详见 work/<书名>/*.log",
                ended_at=time.time())

    def on_cancel():
        # [M3] 取消:先清理 rebuild 中断可能残留的临时 jpg(幂等),再落终态
        _cleanup_jpg_tmp()
        _update(running=False, phase="canceled", stage_label="已取消",
                message="已取消", error=None, ended_at=time.time())

    def should_stop():
        with _lock:
            return STATE["cancel_requested"]

    try:
        gpu_ids = params.get("gpu_ids")
        if not gpu_ids:
            with _lock:
                gpu_ids = STATE["gpu_ids"] or "0"
        process_one(
            pdf,
            scale=params.get("scale", 4),
            target_w=params.get("target_width", 4320),
            model=params.get("model", "realesrgan-x4plus"),
            gpu_ids=gpu_ids,
            extra_args=params.get("extra_args", ""),
            skip_existing=params.get("skip_existing", True),
            extract_workers=params.get("extract_workers", 1),
            monitor=monitor,
            bar=None,
            on_stage=on_stage,
            on_progress=on_progress,
            on_done=on_done,
            should_stop=should_stop,        # [M3]
            on_cancel=on_cancel,            # [M3]
        )
    except Exception as e:
        _update(running=False, phase="error",
                error=str(e), message=f"任务异常: {e}")
```

```python
def start_job(job_id, params):
    with _lock:
        if STATE["running"]:
            raise RuntimeError("已有任务在运行")
        STATE.update(
            running=True, job_id=job_id, pdf=params["pdf"],
            phase="extract", stage_label="提取", page=0, total=None, percent=0,
            message="开始处理", error=None, output_path=None,
            started_at=time.time(), ended_at=None, cancel_requested=False)
    threading.Thread(target=_job_thread, args=(job_id, params), daemon=True).start()


def request_cancel(job_id):
    """[M3] POST /api/jobs/{id}/cancel 的入口。校验后置位,由任务线程 0.4s 内检出。"""
    with _lock:
        if not STATE["running"]:
            return 409, "当前没有正在运行的任务"
        if STATE["job_id"] != job_id:
            return 404, f"任务 {job_id} 不存在或已结束"
        STATE["cancel_requested"] = True
    return 200, "已请求取消,正在终止…"


def _cleanup_jpg_tmp():
    """[M3] 取消后清理 rebuild 中断残留的 output/_jpg_tmp_* 目录(幂等)。"""
    for d in glob.glob(os.path.join(OUT_ROOT, "_jpg_tmp_*")):
        shutil.rmtree(d, ignore_errors=True)
```

**3.4.1 `run_with_progress` 增加 `should_stop`，被取消时返回 `None` 作为约定信号**

```python
def run_with_progress(cmd, log_path, count_fn, total, stage, monitor=None,
                      bar=None, phase=None, on_progress=None, should_stop=None):
    """...原行为不变;新增 should_stop(): 每 0.4s 检查,True 则终止子进程树并返回 None(取消约定)。"""
    with open(log_path, "w", encoding="utf-8", errors="replace") as log:
        proc = subprocess.Popen(cmd, stdout=log, stderr=subprocess.STDOUT)
    t0 = time.time()
    canceled = False
    while proc.poll() is None:
        if should_stop is not None and should_stop():
            canceled = True
            _kill_tree(proc)          # terminate → 3s 未退 → taskkill /T /F
            proc.wait(timeout=10)
            break
        cur = count_fn()
        if bar is not None and monitor is not None:
            bar.render(stage, cur, total, t0, monitor.sample())
        if on_progress is not None:
            on_progress(phase or stage, cur, total)
        time.sleep(0.4)
    cur = count_fn()
    if bar is not None and monitor is not None:
        bar.render(stage, cur, total, t0, monitor.sample())
        bar.newline()
    if on_progress is not None:
        on_progress(phase or stage, cur, total)
    return None if canceled else proc.returncode


def _kill_tree(proc):
    """Windows 下终止子进程树:terminate() 只杀主进程,extract_pages --workers 8 的
    进程池/rebuild 子进程需 taskkill /T /F 连根杀。"""
    proc.terminate()
    try:
        proc.wait(timeout=3)
        return
    except subprocess.TimeoutExpired:
        pass
    try:
        subprocess.run(["taskkill", "/T", "/F", "/PID", str(proc.pid)],
                       capture_output=True, timeout=10)
    except OSError:
        pass
```

> 取消约定：`run_with_progress` 返回 `None` 表示被取消（非 0 仍表示失败）。日志文件已 `"w"` 重建并保留到取消点——**日志可追溯到中断时刻**，符合「严格可追溯」。

**3.4.3 `process_one` 增加 `should_stop`/`on_cancel`，每阶段前/返回处检查**

```python
def process_one(pdf, idx=None, total=None, scale=4, target_w=4320,
                model="realesrgan-x4plus", gpu_ids="0", extra_args="",
                skip_existing=True, extract_workers=1, monitor=None, bar=None,
                on_stage=None, on_progress=None, on_done=None,
                should_stop=None, on_cancel=None):
    """...回调约定新增:
    - should_stop(): 返回 True 表示已请求取消(每阶段轮询与阶段间隙均检查);
    - on_cancel(): 取消落定后调用(不再调 on_done),由调用方写终态。"""

    def canceled():
        return should_stop is not None and should_stop()

    # ...(SKIP 分支 / 目录清理 / pages 探测 原样)...

    if canceled():                      # 开工前取消兜底
        if on_cancel is not None:
            on_cancel()
        return False

    stage("extract", "提取")
    print(f"  [1/3] 提取页面 (zoom 2.0, {extract_workers} 进程)", flush=True)
    rc = run_with_progress([sys.executable, EXTRACT, pdf, src, "--zoom", "2.0",
                            "--workers", str(extract_workers)],
                           os.path.join(work, "extract.log"),
                           lambda: count_png(src), pages, "提取", monitor, bar,
                           "extract", on_progress, should_stop)
    if rc is None:
        if on_cancel is not None:
            on_cancel()
        return False
    if rc != 0:
        print(f"  !! 提取失败 (exit {rc}, 见 {os.path.join(work, 'extract.log')})")
        if on_done is not None:
            on_done(False, None, time.time() - t_start, None)
        return False

    if canceled():                      # 阶段间隙取消兜底
        if on_cancel is not None:
            on_cancel()
        return False

    stage("upscale", f"超分 x{scale}")
    print(f"  [2/3] 超分 x{scale} ({model}, GPU: {gpu_ids})", flush=True)
    rc = upscale(src, up, os.path.join(work, "upscale.log"), model, scale,
                 gpu_ids, extra_args, monitor, bar, "upscale", on_progress,
                 should_stop)
    if rc is None:
        if on_cancel is not None:
            on_cancel()
        return False
    if rc != 0:
        print(f"  !! 超分失败 (exit {rc}, 见 {os.path.join(work, 'upscale.log')})")
        if on_done is not None:
            on_done(False, None, time.time() - t_start, None)
        return False

    if canceled():
        if on_cancel is not None:
            on_cancel()
        return False

    stage("rebuild", "重建")
    print(f"  [3/3] 重建 PDF (目标宽度 {target_w}px)", flush=True)
    rc = run_with_progress([sys.executable, REBUILD, up, out, "--ref-pdf", pdf,
                            "--target-width", str(target_w), "--quality", "90"],
                           os.path.join(work, "rebuild.log"),
                           lambda: count_tmp_jpg(OUT_ROOT), pages, "重建", monitor,
                           bar, "rebuild", on_progress, should_stop)
    if rc is None:
        if on_cancel is not None:
            on_cancel()
        return False
    if rc != 0:
        print(f"  !! 重建失败 (exit {rc}, 见 {os.path.join(work, 'rebuild.log')})")
        if on_done is not None:
            on_done(False, None, time.time() - t_start, None)
        return False

    # ...(正常完成,on_done(True, ...) 原样)...
```

> 取消路径只调 `on_cancel`、不调 `on_done`，避免终态被二次覆盖（竞态防护）。

### 3.5 后端风险自查（取消相关）

- **snapshot() 深拷贝**：取消标志用布尔（`cancel_requested`）而非 `threading.Event`，避免 `copy.deepcopy` 崩溃；
- **阶段间隙取消**：`run_with_progress` 只在轮询中检查，阶段间隙（返回与下一阶段启动之间）的取消由「每阶段前 `canceled()` 检查」兜底；
- **取消后再 POST /api/jobs**：`start_job` 持锁校验 `running`，canceled 后 running=False 才放行，天然防重入；
- **on_cancel 与 on_done 竞态**：取消分支只走 on_cancel，process_one 不再触达 on_done；
- **`_kill_tree` 等待**：terminate 后 `wait(timeout=3)`，仍活才 taskkill；最终 `wait(timeout=10)` 收口，避免僵尸。

### 4.1 ui/src/store/appState.js：三文件全量轮询 + 去环形截断

```js
const LOG_FILES = ["extract", "upscale", "rebuild"];
const MAX_LOG_LINES = 50000;   // [M3] 异常兜底:正常任务日志 <2k 行;超限才截断
```

state 增加截断标记；`pollOnce()` 核心改动（三文件都增量拉；游标回退即文件被重建 → 清空该文件历史）：

```js
logsTruncated: { extract: false, upscale: false, rebuild: false },

async pollOnce() {
  if (document.hidden && !this.running) return;

  const st = await api.getState();
  if (this.state && this.state.job_id !== st.job_id) this.resetLogs();
  this.state = st;

  // 空闲且无历史日志时不拉日志;done/error/canceled 后仍要拉齐最后几行
  const needLogs = st.running
    || this.logs.extract.length || this.logs.upscale.length || this.logs.rebuild.length;
  if (needLogs) {
    for (const f of LOG_FILES) {
      const res = await api.getLogs(f, this.offsets[f]);
      if (res.next_offset < this.offsets[f]) {   // 文件被重建/截断 → 游标回退 → 历史作废
        this.logs[f] = [];
        this.logsTruncated[f] = false;
      }
      this.offsets[f] = res.next_offset;
      if (res.lines.length) {
        this.logs[f].push(...res.lines);
        if (this.logs[f].length > MAX_LOG_LINES) {
          this.logs[f].splice(0, this.logs[f].length - MAX_LOG_LINES);
          this.logsTruncated[f] = true;
        }
      }
    }
  }
  this.lastPoll = Date.now();
  this.pollError = null;
}
```

`resetLogs()` 同步清 `logsTruncated`；**删除** M1 的 `PHASE_LOGS`/`activeFile`（三文件统一轮询后不再需要）。

> 追溯性关键点：新任务以 `"w"` 重建日志文件时文件变小、`next_offset` 回退——前端据此**清空该文件历史**，否则旧行串入新任务（C7）。

## 5. 数据流与交互状态机

### 5.1 轮询时序（单 poller，M1 机制不变）

```
[每 0.8s~10s] GET /api/state
  ├─ job_id 变化 ──▶ resetLogs(三文件 offsets/logs/logsTruncated 清零)
  └─ 更新 state(含 percent/message/phase/ended_at)
[同 tick] GET /api/logs × 3 (extract / upscale / rebuild, 各自 offset)
  ├─ next_offset < 旧 offset ──▶ 该文件 logs 清空重建(文件被新任务重建)
  └─ 追加 lines → LogPanel watch → 若「最后一条可见」则贴底跟随
```

### 5.2 日志追溯与滚动规则表

| 交互 | 行为 |
| ---- | ---- |
| 任务运行中 | 三 tab 实时增量（任意 tab 随时可看，不丢行） |
| **最后一条日志可见（贴底 ≤4px）** | **自动跟随新行下滚** |
| 向上滚动（离开底部） | **停止自动滚动**，自由回看（含最早行） |
| 点「回到底部」 | 立即贴底并恢复跟随 |
| 复制全部 | 当前 tab 全量行复制到剪贴板 |
| 新任务开始 | job_id 变化 → 三文件历史清空 → 只显示新任务日志 |
| 文件被重建但 job_id 未变 | `next_offset` 回退 → 该文件历史清空（防旧行混入） |

### 5.3 取消状态机

```
IDLE/READY ──开始──▶ RUNNING ──取消确认──▶ (cancel_requested=True) ──0.4s 内──▶ CANCELED ──▶ READY(可重跑)
                        │                                                              │
                        └──正常完成/失败──▶ DONE / ERROR ────────────────────────────────┘
```

- `CANCELED`：`phase="canceled"`、`running=False`、进度条定格在取消时百分比、顶栏「已取消」、按钮回 ready；
- 取消后重新开始：`start_job` 复位 `cancel_requested`，src/up 残留由 pipeline 开头清理，成品不落盘。

### 5.4 边界情况

| 边界 | 行为 |
| ---- | ---- |
| SKIP 秒级任务 | percent 0 → done 100 满格绿色；日志面板保持空 |
| total 探测失败（None） | message 退化为页码推进提示；percent 按 cur 展示 |
| 任务异常（error） | 进度条红色定格；日志保留供排查 |
| 空任务（从未开始） | needLogs=false，不发日志请求 |
| 后端中断 | poller 指数退避 + 断连提示（M1 机制） |
| 取消恰好发生在阶段切换间隙 | 下一阶段前 `canceled()` 检查兜底 → 直接落 canceled |
| 取消后 `POST /api/jobs` 409 校验 | running 已被置 False，放行新任务 |

| ---- | ---- | ---- |
| pipeline 参数化（should_stop/on_cancel 透传） | **低** | 三个函数加可选参数（默认 None），CLI 入口 run.py 零影响；主要工作量是阶段返回 `None` 判定的约定与透传 |
| 子进程树终止（_kill_tree） | **中** | Windows `terminate()` 只杀主进程；extract_pages `--workers 8` 内部是 `ProcessPoolExecutor`，进程池必须 `taskkill /T /F` 连根杀；realesrgan/rebuild 为单进程相对简单 |
| 取消状态机 + 路由 + 竞态防护 | **中** | 布尔标志 + 持锁校验 + 阶段间隙兜底检查 + 取消路径只走 on_cancel 不覆盖 on_done；快照深拷贝约束（不能用 Event） |
| 取消后清理（_jpg_tmp_*） | 低 | 幂等 glob+rmtree |
| 前端取消按钮 + 确认框 + 状态回 READY | **低** | M2 状态机复用（canceled 不占按钮态） |
| 测试验证（三阶段各取消 + 残留检查） | **中** | 需真实任务 + tasklist 断言 |
| **综合** | **中等** | 本轮 M3 最高难度项，高于进度条/日志面板；风险集中在 Windows 进程树终止与清理竞态 |

### 7.2 风险表
