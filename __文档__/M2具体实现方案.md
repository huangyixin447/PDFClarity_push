## 0. M2 目标与验收标准

### 0.1 目标

M2 交付**正式的界面一骨架**，替换 M1 的调试视图：

1. **后端**：新增 `GET /api/files/inspect`（选中文件探测：存在性 / 大小 / 页数 / 成品是否已存在）与 `POST /api/files/upload`（浏览器模式上传通道，与桌面壳「原位引用」通道统一）；
2. **前端**：正式布局（顶栏 + 常驻侧边栏 + 主区域界面一）；
   - 界面一（`SelectPage.vue`）：大拖放框（点击 / 拖拽）+ 手动路径输入（桌面壳同通道），选中后显示 文件名 / 大小 / 页数；
   - 侧边栏（`Sidebar.vue`）：系统监控区（CPU / 内存 / GPU，随轮询刷新）+ 参数调节区（对齐 CLI 默认值，运行中禁用）+ **开始按钮状态机**；
3. **遗留修复**：修复 M1 遗留的「HTTP 错误信息不友好」（client.js 错误归一化）与「element-plus 全量引入致 1MB chunk」（按需引入）；
4. **收尾**：最小 PyInstaller 冒烟（uvicorn + 静态页 + API 骨架，提前暴露打包问题）。

> M3 才开始做界面二（缩略图列表 + 日志面板 + 底部进度条）；M2 只交付「能选文件 → 能调参 → 能可靠启动任务」的完整闭环。

## 1. 现状与前置分析（基于已落地的 M1 代码）

### 1.1 M1 已交付的相关事实

- `server/main.py`：`GET /api/state`、`POST /api/jobs`、`GET /api/logs`（`Literal` 白名单 + 字节偏移）、末尾 `ui/dist` 静态托管；`JobRequest` 含 `pdf/scale/target_width/model/gpu_ids/extra_args/extract_workers/skip_existing`；
- `server/logs.py`：`LOG_FILES` 白名单 + `read()` 增量读取（offset>size 自动归零）；
- `server/jobs.py`：全局 `STATE` 字典（`running/job_id/pdf/phase/page/total/percent/message/output_path/error/metrics/gpus/gpu_ids/engine_ok/nvidia_smi`），`snapshot()` 深拷贝；`init()` 已设置 `PYTHONIOENCODING/PYTHONUTF8`（GBK 修复）；
- `core/monitor.py`：`SysMonitor.sample()` 返回 `{"gpu": {idx: {util, mem_used, mem_total, temp, power}}, "cpu": %, "ram": %, "peaks": {gpu, cpu}}`；
- `core/progress.py`：`pdf_page_count(pdf)` 返回页数（失败 None）；
- `ui/`：Vue3 + Vite + Pinia + Element Plus（**全量引入**），`appState.js` 轮询 store（含 job_id 变化 resetLogs、空闲暂停、错误透出），`poller.js` 指数退避。

### 1.2 关键设计决定

1. **两种文件通道收敛为一条链路**：桌面壳（M5）给绝对路径 → `selectByPath(path)`；浏览器（M2 开发态）上传 → 返回 `work/inbox/` 下副本路径 → 同样走 `selectByPath(path)`。前端唯一持有「选中文件的绝对路径」，后续 inspect / 提交任务全部基于该路径；
2. **`inspect` 同时返回 `out_path/out_exists`**：把「成品是否已存在」的判断放到后端（`output/<base>_clear.pdf` 的推导与 core/pipeline 完全一致，前端不拼路径），供 G1 确认框做前置判断；
3. **`upload` 仅做副本**：浏览器上传的文件落到 `work/inbox/`，重名覆盖（副本语义，无需保留历史）；`M4` 再做统一清理；
4. **开始按钮状态机不新增后端字段**：`startState` 由前端根据轮询快照**派生**（running / phase / engine_ok / 选中文件 / 参数合法性），后端仍为唯一事实源，避免双份状态漂移；
5. **按需引入 Element Plus**：`unplugin-auto-import` + `unplugin-vue-components`（`ElementPlusResolver`）；组件模板内 `el-*` 自动注入，**JS 中使用的 `ElMessage/ElMessageBox` 在 `appControl.js` 显式 import 并显式引样式**（不依赖 resolver 对非 SFC 文件的处理，最稳妥）；
6. **监控区数据直接消费 `/api/state`**：`metrics` 是 SysMonitor 最近一次采样快照（≤1s 延迟），前端随既有轮询渲染，无需新接口。

### 1.3 前置风险与 M1 遗留问题映射

| # | 问题 | M2 处理 |
| ---- | ---- | ---- |
| L1 | **任务结束后 `STATE["pdf"]` 残留**，`/api/logs` 返回旧任务日志 | M2 无日志界面，无影响；开始新任务时 `job_id` 变化前端自动 `resetLogs`（M1 已有），**确认无回归**；界面二日志面板在 M3 处理「任务结束展示最后任务日志」 |
| L2 | **进度 `percent` 按页跳变**（upscale 每完成一页才 +1） | M2 无进度条，不涉及；M3 底部进度条按「页粒度 + 页码推进」设计（与 CLI 一致） |
| L3 | **错误信息不友好**（Vite 代理停后端时显示裸 `HTTP 500:`） | **本里程碑修复**：`client.js` 错误归一化——网络失败 →「无法连接后端服务」；超时 →「请求超时」；HTTP 错误解析 FastAPI `detail`（见 §5.3） |
| L4 | **element-plus 全量引入 → 构建 1MB chunk** | **本里程碑修复**：按需引入（见 §5.1） |
| L5 | fastapi 依赖走 `vendor/` 兜底（沙箱限制） | 环境事项：用户本机 `pip install fastapi` 后可删 `vendor/`，M2 代码不依赖 vendor 路径 |

### 3.1 新增 `server/files.py`

```python
"""GET /api/files/inspect 与 POST /api/files/upload 后端实现。

M2 界面一(选择文档)必需:
- inspect : 校验路径合法性 + 探测页数 + 成品是否存在(G1 确认框前置判断);
- upload  : 浏览器模式(开发态/无 pywebview)把本地文件上传到 work/inbox/,
            返回可被后端直接引用的绝对路径,与桌面壳「原位引用」通道统一。
"""
import os

from core.paths import WORK_ROOT, OUT_ROOT
from core.progress import pdf_page_count

MAX_UPLOAD = 500 * 1024 * 1024     # 单文件上限 500MB(4x 超分的源 PDF 一般 < 200MB)
INBOX = os.path.join(WORK_ROOT, "inbox")


def _out_path_for(pdf):
    """推导成品路径,与 core/pipeline.process_one 的 out 计算保持一致。"""
    base = os.path.splitext(os.path.basename(pdf))[0]
    return os.path.join(OUT_ROOT, base + "_clear.pdf")


def inspect(path):
    """选中文件探测。路径非法时返回 exists=False,不抛异常(前端直接展示)。

    返回: {exists, name, size, pages, out_path, out_exists}
    - pages: pdf_page_count 结果,探测失败为 None;
    - out_path/out_exists: 供前端 G1「成品已存在」确认框做前置判断。
    """
    empty = {"exists": False, "name": None, "size": None, "pages": None,
             "out_path": None, "out_exists": False}
    if not path or not isinstance(path, str) or not path.lower().endswith(".pdf"):
        return empty
    try:
        if not os.path.isfile(path):
            return empty
        out = _out_path_for(path)
        return {"exists": True, "name": os.path.basename(path),
                "size": os.path.getsize(path),
                "pages": pdf_page_count(path),
                "out_path": out,
                "out_exists": os.path.isfile(out)}
    except OSError:
        return empty
```

### 3.2 修改 `server/main.py`

在 M1 代码上做三处增量（imports、两个新路由、版本号）：

```python
"""FastAPI 应用:FastAPI 骨架 + POST /api/jobs + GET /api/state + GET /api/logs。

M0 交付基础接口;M1 新增日志轮询接口与 ui/dist 静态托管;M2 新增文件探测/上传。
"""
import os
import time
import uuid
from contextlib import asynccontextmanager
from typing import Literal

from fastapi import FastAPI, File, HTTPException, Query, UploadFile
from fastapi.staticfiles import StaticFiles
from pydantic import BaseModel, Field

from core.paths import HERE
from server import files, jobs, logs


@asynccontextmanager
async def lifespan(_app):
    jobs.init()
    yield
    jobs.shutdown()


app = FastAPI(title="PDFClarity", version="0.3.0", lifespan=lifespan)


class JobRequest(BaseModel):
    pdf: str
    scale: int = Field(4, ge=2, le=4)          # 2 或 4
    target_width: int = Field(4320, ge=0)       # 0 = 保留完整尺寸
    model: str = "realesrgan-x4plus"
    gpu_ids: str | None = None                 # None = 用自检自动选择结果
    extra_args: str = ""
    extract_workers: int = Field(1, ge=1)
    skip_existing: bool = True


@app.get("/api/state")
def get_state():
    """返回全局状态快照(任务进度 + 系统指标 + 自检结果)。"""
    return jobs.snapshot()


@app.post("/api/jobs")
def create_job(req: JobRequest):
    """创建超分任务,后台线程执行。成功返回 job_id,冲突返回 409。"""
    st = jobs.snapshot()
    if st["running"]:
        raise HTTPException(409, "已有任务在运行")
    if not st["engine_ok"]:
        raise HTTPException(400, "超分引擎缺失,无法开始(检查 bin/realesrgan/)")
    if not os.path.isfile(req.pdf) or not req.pdf.lower().endswith(".pdf"):
        raise HTTPException(400, "pdf 路径不存在或不是 PDF 文件")

    job_id = f"{int(time.time())}-{uuid.uuid4().hex[:8]}"
    try:
        jobs.start_job(job_id, req.model_dump())
    except RuntimeError as e:
        raise HTTPException(409, str(e))
    return {"job_id": job_id, "status": "started"}


@app.get("/api/logs")
def get_logs(
    file: Literal["extract", "upscale", "rebuild"] = "extract",
    offset: int = Query(0, ge=0),
):
    """轮询日志:按字节偏移增量读取当前任务的日志文件。"""
    return logs.read(jobs.snapshot()["pdf"], file, offset)


@app.get("/api/files/inspect")
def inspect_file(path: str = Query(...)):
    """选中文件探测:存在性 / 大小 / 页数 / 成品是否已存在。"""
    return files.inspect(path)


@app.post("/api/files/upload")
async def upload_file(file: UploadFile = File(...)):
    """浏览器模式上传 PDF 到 work/inbox/,返回可处理路径。

    - 仅接受 .pdf;流式写入并限制 500MB(超限删除已写部分后返回 413);
    - 重名覆盖(副本语义);桌面壳模式下本接口不使用(直接给绝对路径)。
    """
    name = os.path.basename(file.filename or "")
    if not name.lower().endswith(".pdf"):
        raise HTTPException(400, "仅支持 PDF 文件")
    os.makedirs(files.INBOX, exist_ok=True)
    dst = os.path.join(files.INBOX, name)
    size = 0
    try:
        with open(dst, "wb") as out:
            while True:
                chunk = await file.read(1024 * 1024)
                if not chunk:
                    break
                size += len(chunk)
                if size > files.MAX_UPLOAD:
                    raise HTTPException(413, "文件超过 500MB 上限")
                out.write(chunk)
    except HTTPException:
        try:
            os.remove(dst)            # 超限时删除半成品
        except OSError:
            pass
        raise
    return {"path": dst, "name": name, "size": size}


# ---------- 前端静态托管(存在 ui/dist 时挂载,必须在 API 路由之后) ----------

_UI_DIST = os.path.join(HERE, "ui", "dist")
if os.path.isdir(_UI_DIST):
    app.mount("/", StaticFiles(directory=_UI_DIST, html=True), name="ui")
```

> 变更对照：新增 import（`File`/`UploadFile`）、`from server import files`、`inspect_file`/`upload_file` 两个路由、version 0.2.0 → 0.3.0；其余 M1 代码原样不动。

### 4.4 `ui/src/api/client.js`（重写：错误归一化 + 新增方法）

```js
// REST 客户端:统一 fetch 封装 + 超时 + 错误归一化。
// M2 修复(M1 遗留 L3):网络失败 / 超时 / HTTP 错误给出可读信息,而非裸 "HTTP 500:"。
const BASE = "/api";
const TIMEOUT = 10000;

async function request(url, { body = null, isForm = false, timeout = TIMEOUT } = {}) {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), timeout);
  try {
    let res;
    try {
      res = await fetch(BASE + url, {
        method: body ? "POST" : "GET",
        headers: isForm ? {} : { "Content-Type": "application/json" },
        body,
        signal: ctrl.signal,
      });
    } catch (e) {
      if (e.name === "AbortError") throw new Error("请求超时,请检查后端服务");
      throw new Error("无法连接后端服务,请确认服务已启动");
    }
    if (!res.ok) {
      // 优先解析 FastAPI 的 {"detail": ...}
      let detail = "";
      try { const j = await res.json(); detail = j.detail ?? ""; } catch { /* 非 JSON 响应体 */ }
      if (typeof detail === "string" && detail) {
        throw new Error(`HTTP ${res.status}: ${detail.slice(0, 200)}`);
      }
      const text = await res.text().catch(() => "");
      throw new Error(`HTTP ${res.status}: ${text.slice(0, 200)}`);
    }
    return res.json();
  } finally {
    clearTimeout(timer);
  }
}

export const api = {
  getState: () => request("/state"),
  getLogs: (file, offset) => request(`/logs?file=${file}&offset=${offset}`),
  inspect: (path) => request(`/files/inspect?path=${encodeURIComponent(path)}`),
  upload: (file) => {
    const fd = new FormData();
    fd.append("file", file);
    return request("/files/upload", { body: fd, isForm: true, timeout: 60000 });
  },
  createJob: (payload) => request("/jobs", { body: JSON.stringify(payload) }),
  // M4 追加: cancelJob(id) => request(`/jobs/${id}/cancel`, { method: "POST" })
};
```

```js
import { ElMessage, ElMessageBox } from "element-plus";
// 按需场景下显式引入这两个 JS 组件的样式(不依赖 resolver 处理非 SFC 文件)
import "element-plus/es/components/message/style/css";
import "element-plus/es/components/message-box/style/css";

import { api } from "../api/client";
import { useAppState } from "./appState";

// 模型列表(与 bin/realesrgan/models/ 下的 param 文件对应)
const MODELS = ["realesrgan-x4plus", "realesrgan-x4plus-anime"];
let busy = false;                // 模块级连点保护(selectByPath 防并发 inspect)

export const useAppControl = defineStore("appControl", {
  state: () => ({
    selectedFile: null,            // 当前选中 PDF 的绝对路径(后端可处理)
    fileInfo: null,                // inspect 结果 {name, size, pages, out_path, out_exists}
    view: "select",                // select | work(M3 切到界面二)
    params: {
      scale: 4,
      target_width: 4320,
      model: "realesrgan-x4plus",
      gpu_ids: null,               // null = 用后端自检的自动选择结果
      extract_workers: 8,          // 与 CLI 默认 min(8, cpu_count) 对齐;
                                  // 机器核数 < 8 时由 App.vue 首轮轮询后收敛(见 §4.9)
      skip_existing: true,
    },
  }),

  getters: {
    running: () => useAppState().running,
    phase: () => useAppState().phase,
    engineOk: () => useAppState().state?.engine_ok ?? false,
    cpuCount: () => useAppState().state?.cpu_count ?? 8,

    // 参数合法性与 startState 均为派生值,后端 /api/state 仍为唯一事实源
    paramsValid(s) {
      const p = s.params;
      if (![2, 4].includes(p.scale)) return false;
      if (!Number.isInteger(p.target_width) || p.target_width < 0) return false;
      if (!MODELS.includes(p.model)) return false;
      if (!Number.isInteger(p.extract_workers)
          || p.extract_workers < 1
          || p.extract_workers > this.cpuCount) return false;
      return true;
    },

    // 状态机:IDLE(未选/非法) → READY → RUNNING。
    // DONE/ERROR 是任务终态,只由顶栏徽标展示,不占用按钮状态——
    // 结束后用户可换文件或直接重跑,故按钮回到 READY(文案在组件层区分「重新超分」)。
    startState(s) {
      if (this.running) return "running";
      return s.selectedFile && this.paramsValid && this.engineOk ? "ready" : "idle";
    },

    // 侧边栏 GPU 下拉选项:自动选择 + 后端自检枚举
    gpuOptions() {
      const gpus = useAppState().state?.gpus ?? [];
      return [
        { label: "自动选择", value: null },
        ...gpus.map(([i, n]) => ({ label: `[${i}] ${n}`, value: String(i) })),
      ];
    },
  },

  actions: {
    // 两条通道(桌面壳路径 / 浏览器上传副本)统一收敛到这里。
    // busy 防连点:快速连选/连点「探测」时丢弃后到的并发请求(R4)。
    async selectByPath(path) {
      if (busy) return;
      busy = true;
      try {
        const info = await api.inspect(path);
        if (!info.exists) throw new Error("文件不存在或不是 PDF");
        this.selectedFile = path;
        this.fileInfo = info;
      } finally {
        busy = false;
      }
    },

    async selectFile(file) {
      const res = await api.upload(file);
      await this.selectByPath(res.path);
    },

    clearFile() {
      this.selectedFile = null;
      this.fileInfo = null;
    },

    // 开始任务。G1:成品已存在且开启跳过 → 确认「跳过 / 强制重做」。
    async start() {
      if (this.startState !== "ready") return;
      let skip = this.params.skip_existing;
      if (skip && this.fileInfo?.out_exists) {
        try {
          await ElMessageBox.confirm(
            "检测到同名成品已存在,如何处理?",
            "成品已存在",
            { confirmButtonText: "跳过(不重跑)", cancelButtonText: "强制重做",
              type: "warning", distinguishCancelAndClose: true });
          // 点「跳过」→ 保持 skip_existing=True,任务秒级 SKIP
        } catch (action) {
          // 点「强制重做」→ 关掉跳过,真实重跑
          if (action === "cancel") skip = false;
          else return;              // 点右上角关闭 → 放弃
        }
      }
      try {
        await api.createJob({ pdf: this.selectedFile, ...this.params, skip_existing: skip });
        ElMessage.success("任务已开始");
      } catch (e) {
        ElMessage.error(e.message);
      }
    },
  },
});
```

> `distinguishCancelAndClose: true`：区分「强制重做」（cancel）与「点右上角 × 关闭」（close，放弃操作），避免误触发。
> `skip_existing` 从 params 取出后传给本次请求；后续任务仍用 params 原值。

## 5. 数据流与状态机

### 5.1 按需引入 Element Plus（L4 修复原理）

M1 是 `app.use(ElementPlus)` + 全量 `index.css`，构建出一个 ~1MB 的 chunk。M2 改为 `unplugin-vue-components` 的 `ElementPlusResolver`：

- **模板内 `el-*` 组件**：resolver 扫描 `<template>`，只引入用到的组件及其样式（`el-card/el-progress/el-form/...` 按需打包）；
- **JS API（`ElMessage` / `ElMessageBox`）**：resolver 只处理 SFC 模板，不处理 `.js` 文件里的 import——所以 `appControl.js` 与 `SelectPage.vue` 中**显式** `import "element-plus/es/components/message/style/css"`（及 message-box 样式）；
- 效果：`npm run build` 后单 chunk 应 < 300KB，无 >500KB 警告（C9）。

> 注意：本方案不生成 `auto-imports.d.ts` / `components.d.ts`（`dts: false`），纯 JS 项目不需要。

### 5.2 组件与数据流

```
后端(唯一事实源: jobs.STATE)
   │  GET /api/state(0.8s~10s 轮询,失败退避)
   ▼
appState.state(轮询快照)
   ├─ metrics ──────────────► Sidebar 监控区(CPU/内存/GPU 卡片)
   ├─ phase / running ───────► 顶栏状态徽标 + 开始按钮(派生 startState)
   ├─ gpus / engine_ok ─────► Sidebar GPU 下拉 / 开始按钮可用性
   └─ cpu_count ────────────► Sidebar 线程数上限 + App.vue 首轮收敛

操作输入(前端持有):
   浏览器文件 ─POST /api/files/upload─> work/inbox/ 副本 ─┐
                                                          ▼
   桌面壳绝对路径 ───────────────────────────────────► selectByPath(path)
                                                          │ GET /api/files/inspect
                                                          ▼
                                            selectedFile + fileInfo(含 out_exists)
                                                          │ POST /api/jobs
                                                          ▼
                                            后端线程 → /api/state(running/phase/percent)
```

- **唯一事实源仍是后端 `jobs.STATE`**：前端所有「状态」都是派生值（getter），从不自行置位 running/phase；
- **`job_id` 变化 → `appState.resetLogs()`**（M1 已有）：换文件重跑时日志游标自动归零，M2 虽无日志界面，但该机制保证「两轮任务互不污染」（C8，L1 无回归确认）；
- **`params` 与 `selectedFile` 是仅有的两处前端输入**，提交任务时整体序列化给 `/api/jobs`。

### 5.3 错误归一化链路（L3 修复原理）

M1 的 `HTTP 500:` 裸错误源自 fetch 层未做任何解析。M2 在 `client.js` 统一处理，全链路如下：

```
fetch 抛错(网络/代理挂) ──► "无法连接后端服务,请确认服务已启动"
fetch 抛错(AbortController) ─► "请求超时,请检查后端服务"
HTTP 非 2xx(JSON detail) ───► "HTTP 400: 超分引擎缺失,无法开始(检查 bin/realesrgan/)"
HTTP 非 2xx(非 JSON) ───────► "HTTP 500: <响应正文前 200 字符>"
```

错误去向：
- **轮询错误**：`poller` catch → `appState.pollError` → 顶栏「连接中断」（红点），退避期间持续提示；
- **操作错误**：`selectByPath` / `createJob` 抛出的 `Error(message)` → 组件 catch → `ElMessage.error(e.message)`，界面友好展示。

### 5.4 开始按钮状态机

| startState | 触发条件 | 按钮表现 | 提示文案 |
| ---- | ---- | ---- | ---- |
| `running` | 轮询快照 `running === true` | loading + 禁用 | 「正在超分… 请勿关闭窗口或重复点击」 |
| `ready` | 已选文件 ∧ 参数合法 ∧ `engine_ok` | 可点击（primary） | 「就绪，点击开始超分」；上一任务 done/error 后显示「重新超分」 |
| `idle` | 其余情况 | 禁用 | 分因提示：未选文件 / 参数不合法 / 引擎缺失 |

状态迁移（全部由事件 + 轮询驱动，前端无自转状态）：

```
启动 ──► idle(未选文件)
selectByPath 成功 ──► ready
点击开始(start()) ──► 提交成功 → ElMessage「任务已开始」
下一轮轮询 ──► running(loading)
on_done / on_error ──► 快照 phase=done|error → 顶栏徽标切换;按钮回 ready(可重跑)
G1(成品已存在): skip_existing ∧ out_exists → ElMessageBox.confirm
    ├─「跳过」→ skip_existing=true  → 秒级 SKIP(phase=done)
    └─「强制重做」→ skip_existing=false → 真实重跑
```

> 防重入由后端保证（`start_job` 持锁置 `running`，M0 已修）；前端 `:disabled` 只是体验层，不是安全边界。

```powershell
python -S -m PyInstaller --noconfirm --clean --onefile -n PDFClarity_smoke `
  --add-data "ui/dist;ui/dist" app.py
# 实测:分析+打包共 ~94s,产出 dist\PDFClarity_smoke.exe(~39MB)
```

## 7. 风险与注意事项

| # | 风险 | 对策 / 说明 |
| ---- | ---- | ---- |
| R1 | fastapi 在 `vendor/`（沙箱限制） | 后端启动与 PyInstaller 均需 `--paths vendor`；用户机 `pip install fastapi` 后可删 `vendor/`（L5）。**代码不依赖 vendor 路径** |
