## 0. M1 目标与验收标准

### 0.1 目标

M1 打通「后端状态/日志 → 前端轮询」通道，建立前端地基：

1. **后端**：新增 `GET /api/logs` 增量日志接口（字节偏移断点续读）；
2. **后端修复**：在服务端环境统一子进程 UTF-8 输出（`PYTHONIOENCODING`），消除「服务端跑出的 log 是 GBK 乱码」的隐患（见 §1.3）；
3. **前端**：新建 `ui/` 脚手架（Vue3 + Vite + Pinia + Element Plus），实现**统一定时器轮询器**（失败指数退避、空闲/页面隐藏暂停、job_id 变更自动重置日志游标）；
4. **联调**：提供一个最简 `App.vue` 调试视图，肉眼验证「阶段/进度/日志实时刷新」。

> M2/M3 才开始做正式界面（选择文档页、工作页、侧边栏、进度条）；M1 只交付「数据能持续、正确地流动」。

### 0.2 验收标准（M1 完成的判定）

| # | 验收项 | 判定方法 |
| ---- | ---- | ---- |
| C1 | `/api/logs` 增量正确 | 对运行中的任务连续两次请求：第二次以第一次返回的 `next_offset` 作为 `offset`，两批 `lines` 首尾衔接、无重复无遗漏，且 `next_offset` 单调不减（文件持续增长时严格递增） |
| C2 | 日志重写后游标归零 | 新任务开始时 `extract.log` 被以 `w` 模式重建（文件变小）；传旧的 `offset`（> 新文件大小）自动归零返回全文 |
| C3 | 无任务时返回空 | `pdf=None` 时返回 `{exists:false, lines:[], next_offset:0}` |
| C4 | 非法 `file` 参数被拒 | `GET /api/logs?file=..%2F..%2Fetc%2Fpasswd` 返回 **422**（路径穿越白名单防护） |
| C5 | 服务端 log 无乱码 | 通过 `POST /api/jobs` 跑完一个小 PDF 后，`work/<base>/extract.log` 中无 `\ufffd` 替换符（GBK 修复生效） |
| C6 | 前端轮询联通 | `npm run dev` 打开后，`App.vue` 的阶段/进度/日志随任务实时刷新 |
| C7 | 轮询失败自动恢复 | 任务运行中停掉后端 → 前端显示错误且退避重试；重启后端 → 前端自动恢复轮询 |
| C8 | 空闲/隐藏暂停 | 无任务且标签页隐藏时，DevTools Network 面板无 `/api/state` 请求 |

## 1. 现状与前置分析（基于已落地的 M0 代码）

### 1.1 M0 已交付的相关事实

- `server/jobs.py`：全局 `STATE` 字典（含 `pdf`、`job_id`、`phase`、`page`、`total`、`percent` 等），`snapshot()` 返回深拷贝；`start_job` 持锁同步置 `running=True`（防重入竞态已修复）；
- `server/main.py`：`GET /api/state`（轮询主接口，M0 已可用）、`POST /api/jobs`、lifespan 启动 `jobs.init()`；
- `core/pipeline.py`：每个 PDF 的日志落在 `work/<书名>/extract.log`、`upscale.log`、`rebuild.log`（`core/paths.WORK_ROOT` 下）；
- `app.py`：`uvicorn.run(app, host="127.0.0.1", port=8000)`。

### 1.2 关键设计决定

1. **游标单位 = 字节偏移**：日志是 append-only 文本，按字节断点最稳（行号会因中途加行而漂移）；`next_offset` 由后端返回、前端保存并传回，后端不存游标（无状态、可水平重启）；
2. **二进制读取 + 增量解码**：以 `rb` 读、按 `bytes` 长度计算 `next_offset`（字节精确），解码用 `errors="replace"` 兜底，避免文本模式读-再编码的字节漂移；
3. **`file` 参数白名单**：只允许 `extract / upscale / rebuild` 三键，映射到固定文件名，杜绝路径穿越；
4. **前端单一定时器**：`setTimeout` 链式调度（非 `setInterval`），一次 tick 完成后再排下一次；失败指数退避（0.8s → 最大 10s）；`document.hidden && !running` 时跳过网络请求（空闲暂停）。

### 1.3 前置风险（M0 代码复核发现，M1 必须一并修复）

**风险：服务端跑出的 log 可能是 GBK 乱码。**

- `core/pipeline.run_with_progress` 用 `open(log_path, "w", encoding="utf-8")` 打开日志文件，`Popen(stdout=log)` 把子进程 stdout 原样写入该文件；
- CLI 模式：`run.py::main()` 会 `os.environ.setdefault("PYTHONIOENCODING", "utf-8")`，所以子进程（extract_pages.py / rebuild_pdf.py 的 python）写 stdout 用 UTF-8，log 文件干净；
- **服务端模式：`server/jobs.py` 从未设置该变量** → 子进程在无控制台管道下按 locale（中文 Windows 为 GBK）编码写 stdout → 经 UTF-8 文件对象解码后变成 `\ufffd` 乱码。

**修复**：`jobs.init()` 顶部追加环境变量设置（见 §3.3）。

## 3. 后端改动（具体代码）

### 3.1 新增 `server/logs.py`

```python
"""GET /api/logs 后端实现:按字节偏移增量读取当前任务的日志文件。

设计要点:
- 游标单位是字节偏移,由调用方(前端)持有并传回,后端无状态;
- 二进制读取,next_offset = 旧 offset + 本次实际读到的字节数(精确);
- file 参数只允许三个白名单键,映射到固定文件名,杜绝路径穿越;
- 日志被新任务以 "w" 模式重建(文件变小)时,旧 offset 自动归零。
"""
import os

from core.paths import WORK_ROOT

# 白名单:逻辑键 -> 日志文件名。禁止把任意文件名/路径直接拼进路径。
LOG_FILES = {
    "extract": "extract.log",
    "upscale": "upscale.log",
    "rebuild": "rebuild.log",
}

_MAX_LINES = 1000          # 单次返回上限(防御异常增长)
_READ_CHUNK = 256 * 1024   # 单次最多读 256KB,防止日志爆炸时一次读入过大


def _log_path(pdf, file):
    """由输入 PDF 推导日志路径,与 core.pipeline 的 work/<书名>/<file> 保持一致。"""
    base = os.path.splitext(os.path.basename(pdf))[0]
    return os.path.join(WORK_ROOT, base, LOG_FILES[file])


def read(pdf, file, offset=0):
    """增量读取日志文件。

    参数:
        pdf   : STATE["pdf"],即输入 PDF 的绝对路径(可能为 None)
        file  : LOG_FILES 的白名单键("extract"/"upscale"/"rebuild")
        offset: 调用方持有的字节偏移(必须 >= 0)

    返回:
        {"file", "exists", "offset", "next_offset", "lines"}
    - pdf 为空 / 文件不存在 : exists=False, lines=[], next_offset=0;
    - offset 超过文件大小   : 视为日志被重写,offset 归零后返回全文;
    - 正常                 : 从 offset 读到文件尾,lines 为该区间按行切分的结果。
    """
    if not pdf:
        return {"file": file, "exists": False, "offset": offset,
                "next_offset": 0, "lines": []}

    path = _log_path(pdf, file)
    try:
        size = os.path.getsize(path)
    except OSError:
        return {"file": file, "exists": False, "offset": offset,
                "next_offset": 0, "lines": []}

    if offset > size:                     # 文件被重建/截断,游标失效
        offset = 0
    if offset < 0:
        offset = 0

    try:
        with open(path, "rb") as f:
            f.seek(offset)
            raw = f.read(_READ_CHUNK)
    except OSError:
        return {"file": file, "exists": True, "offset": offset,
                "next_offset": offset, "lines": []}

    next_offset = offset + len(raw)       # 字节精确,不受多字节字符影响
    lines = raw.decode("utf-8", errors="replace").splitlines()
    if len(lines) > _MAX_LINES:
        lines = lines[-_MAX_LINES:]
    return {"file": file, "exists": True, "offset": offset,
            "next_offset": next_offset, "lines": lines}
```

> 说明：`_READ_CHUNK` 限单次 256KB；若日志在两次轮询间增长超过该值，前端以 `next_offset` 续读即可追上（多读几轮），不会丢内容（`next_offset` 恒为实际读取的末尾字节）。唯一理论瑕疵是「读满 256KB 恰在某行中间截断」会使该行在显示时断成两行——真实日志单行远小于 256KB，属不可达边界。

### 3.2 修改 `server/main.py`

在现有文件上做三处增量（imports、新路由、静态托管）：

```python
"""FastAPI 应用:FastAPI 骨架 + POST /api/jobs + GET /api/state + GET /api/logs。

M0 交付基础接口;M1 新增日志轮询接口与 ui/dist 静态托管。
"""
import os
import time
import uuid
from contextlib import asynccontextmanager
from typing import Literal

from fastapi import FastAPI, HTTPException, Query
from fastapi.staticfiles import StaticFiles
from pydantic import BaseModel, Field

from core.paths import HERE
from server import jobs, logs

# ---------- 应用生命周期 ----------

@asynccontextmanager
async def lifespan(_app):
    jobs.init()
    yield
    jobs.shutdown()


app = FastAPI(title="PDFClarity", version="0.2.0", lifespan=lifespan)

# ---------- 请求模型 ----------

class JobRequest(BaseModel):
    pdf: str
    scale: int = Field(4, ge=2, le=4)          # 2 或 4
    target_width: int = Field(4320, ge=0)       # 0 = 保留完整尺寸
    model: str = "realesrgan-x4plus"
    gpu_ids: str | None = None                 # None = 用自检自动选择结果
    extra_args: str = ""
    extract_workers: int = Field(1, ge=1)
    skip_existing: bool = True

# ---------- REST 接口 ----------

@app.get("/api/state")
def get_state():
    """返回全局状态快照(任务进度 + 系统指标 + 自检结果)。"""
    return jobs.snapshot()


@app.post("/api/jobs")
def create_job(req: JobRequest):
    """创建超分任务,后台线程执行。成功返回 job_id,冲突返回 409。"""
    st = jobs.snapshot()
    if st["running"]:
        raise HTTPException(409, "已有任务在运行")
    if not st["engine_ok"]:
        raise HTTPException(400, "超分引擎缺失,无法开始(检查 bin/realesrgan/)")
    if not os.path.isfile(req.pdf) or not req.pdf.lower().endswith(".pdf"):
        raise HTTPException(400, "pdf 路径不存在或不是 PDF 文件")

    job_id = f"{int(time.time())}-{uuid.uuid4().hex[:8]}"
    try:
        jobs.start_job(job_id, req.model_dump())
    except RuntimeError as e:
        raise HTTPException(409, str(e))
    return {"job_id": job_id, "status": "started"}


@app.get("/api/logs")
def get_logs(
    file: Literal["extract", "upscale", "rebuild"] = "extract",
    offset: int = Query(0, ge=0),
):
    """轮询日志:按字节偏移增量读取当前任务的日志文件。

    - file 用 Literal 限定为三个白名单键(其余值 FastAPI 自动回 422);
    - 无任务时返回空,offset 由前端持有并传回。
    """
    return logs.read(jobs.snapshot()["pdf"], file, offset)

# ---------- 前端静态托管(存在 ui/dist 时挂载,必须在 API 路由之后) ----------

_UI_DIST = os.path.join(HERE, "ui", "dist")
if os.path.isdir(_UI_DIST):
    app.mount("/", StaticFiles(directory=_UI_DIST, html=True), name="ui")
```

> 变更对照：仅新增 `import`（`Literal`/`Query`/`StaticFiles`/`HERE`/`logs`）、`get_logs` 路由、文件末尾的静态挂载；M0 已有代码不动。

// REST 客户端:统一 fetch 封装 + 超时 + 错误归一化。
const BASE = "/api";

async function fetchJSON(url, opts = {}) {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), 10000);   // 10s 超时
  try {
    const res = await fetch(BASE + url, {
      headers: { "Content-Type": "application/json" },
      signal: ctrl.signal,
      ...opts,
    });
    if (!res.ok) {
      const text = await res.text().catch(() => "");
      throw new Error(`HTTP ${res.status}: ${text.slice(0, 200)}`);
    }
    return res.json();
  } finally {
    clearTimeout(timer);
  }
}

export const api = {
  getState: () => fetchJSON("/state"),
  getLogs: (file, offset) => fetchJSON(`/logs?file=${file}&offset=${offset}`),

### 4.6 `ui/src/api/poller.js`

```js
// 轮询器:单一 setTimeout 链式调度(不是 setInterval),避免 tick 重叠;
// 失败指数退避(0.8s 起,最大 10s),下一次 tick 永远在上一次结束后才排。
export function createPoller(tick, { base = 800, max = 10000 } = {}) {
  let timer = null;
  let fails = 0;
  let running = false;
  let onError = null;                          // 错误透出回调,由 setOnError 注入

  const interval = () => Math.min(base * 2 ** fails, max);

  async function loop() {
    try {
      await tick();
      fails = 0;
    } catch (e) {
      fails = Math.min(fails + 1, 8);          // 最多退避到 max
      onError?.(e);                             // 通知调用方(store),用于界面提示
    }
    if (running) timer = setTimeout(loop, interval());
  }

  return {
    start() {
      if (running) return;
      running = true;
      loop();
    },
    stop() {
      running = false;
      if (timer) {
        clearTimeout(timer);
        timer = null;
      }
    },
    reset() { fails = 0; },
    setOnError(fn) { onError = fn; },          // 用闭包注入,避免 this 绑定问题
  };
}
```

### 4.7 `ui/src/store/appState.js`

```js
import { defineStore } from "pinia";
import { api } from "../api/client";
import { createPoller } from "../api/poller";

// 阶段 -> 对应日志文件的逻辑键(与后端 LOG_FILES 白名单一致)
const PHASE_LOGS = { extract: "extract", upscale: "upscale", rebuild: "rebuild" };
const MAX_LOG_LINES = 2000;          // 每文件环形缓冲上限,防长任务内存膨胀

export const useAppState = defineStore("appState", {
  state: () => ({
    state: null,                       // GET /api/state 最近一次快照
    logs: { extract: [], upscale: [], rebuild: [] },
    offsets: { extract: 0, upscale: 0, rebuild: 0 },
    activeFile: "extract",
    pollError: null,                   // 最近一次轮询错误(用于界面提示)
    lastPoll: null,                    // 最近一次成功时间戳
    poller: null,                      // 轮询器实例(start() 中创建)
  }),

  getters: {
    running: (s) => s.state?.running ?? false,
    phase: (s) => s.state?.phase ?? "idle",
    percent: (s) => s.state?.percent ?? 0,
  },

  actions: {
    // 一次完整轮询:state + 当前阶段日志,并行发起
    async pollOnce() {
      // 空闲暂停:页面隐藏且无任务时,跳过本次(不发网络请求)
      if (document.hidden && !this.running) return;

      const st = await api.getState();
      // job_id 变化 => 新任务,日志游标全部归零(旧日志清空)
      if (this.state && this.state.job_id !== st.job_id) this.resetLogs();
      this.state = st;

      const file = PHASE_LOGS[st.phase] ?? this.activeFile;
      this.activeFile = file;
      const res = await api.getLogs(file, this.offsets[file]);
      this.offsets[file] = res.next_offset;
      if (res.lines.length) {
        this.logs[file].push(...res.lines);
        if (this.logs[file].length > MAX_LOG_LINES) {
          this.logs[file].splice(0, this.logs[file].length - MAX_LOG_LINES);
        }
      }
      this.lastPoll = Date.now();
      this.pollError = null;
    },

    resetLogs() {
      this.logs = { extract: [], upscale: [], rebuild: [] };
      this.offsets = { extract: 0, upscale: 0, rebuild: 0 };
    },

    start() {
      if (!this.poller) {
        this.poller = createPoller(() => this.pollOnce());
        // 轮询失败时把错误透出给界面(退避期间仍可提示用户)
        this.poller.setOnError((e) => { this.pollError = e.message; });
      }
      this.poller.start();
    },
    stop() {
      this.poller?.stop();
    },
  },
});
```

> 说明：错误透出链路 —— `pollOnce` 抛出的异常由 `poller.js` 的 `catch` 捕获（同时触发指数退避），并调用 `setOnError` 注入的回调把 `e` 写入 `pollError`；退避期间界面可据此提示。`pollOnce` 内部**不**自行吞错，保证每轮最多触发一次错误回调，且后端恢复后首个成功 tick 即清空 `pollError` 并归零退避。

## 5. 数据流与时序

### 5.1 轮询时序（正常路径）

```
前端(poller, 0.8s)              后端(FastAPI)
   │  GET /api/state               │
   ├──────────────────────────────▶│ jobs.snapshot() → STATE 深拷贝
   │ ◀────────── 快照 ─────────────┤
   │  GET /api/logs?file=extract   │
   │  &offset=<上次next_offset>     │ logs.read(pdf, file, offset)
   ├──────────────────────────────▶│   读 work/<base>/extract.log[offset:]
   │ ◀──── {lines, next_offset} ───┤
   │  → 更新 store(state/logs/offset)
   │  setTimeout(loop, 0.8s) ← 排队下一次
```

### 5.2 关键状态转移

| 事件 | store 变化 |
| ---- | ---- |
| 首次轮询 | `state` 填充；`job_id` 首次出现不触发重置 |
| 新任务（`job_id` 变化） | `resetLogs()`：清空 3 个日志缓冲与游标 |
| 阶段切换（phase: extract→upscale） | `activeFile` 切到对应键，后续 `/api/logs` 读新文件（该文件 offset 为 0，从头读） |
| 轮询抛错（后端停） | `pollError` 设置；poller 退避；不崩 |
| 后端恢复 | tick 成功 → `pollError=null`、退避归零 |
| 页面隐藏且无任务 | `pollOnce` 首行 return，不发请求 |

### 5.3 边界：阶段内日志文件尚不存在

任务刚开始时 `extract.log` 尚未创建 → `logs.read` 返回 `exists=false, next_offset=0`；每轮都会重试，文件一旦出现，下一次轮询即可读到内容（游标从 0 起，正确）。

## 7. 风险与注意事项

1. **GBK 乱码（必修）**：§3.3 的 `PYTHONIOENCODING` 必须在 `jobs.init()` 中**先于任何子进程启动前**设置；若漏设，M3 日志面板会满屏 `\ufffd`。CLI 侧已由 run.py 设置，服务端不能遗漏；
2. **路径穿越**：`/api/logs` 的 `file` 参数用 `Literal` 白名单，**禁止**直接拼接用户输入到文件路径；若未来扩展新日志文件，先加进 `LOG_FILES` 白名单；
3. **游标语义**：`next_offset` 是字节偏移，前端必须原样回传；**不要在客户端把行数当 offset**。`read` 对 `offset>size` 自动归零，保证新任务/截断后能自愈；
4. **单 tick 不重叠**：轮询用 `setTimeout` 链（`poller.js`），不是 `setInterval`——避免一次请求慢导致 tick 堆积；
5. **日志内存上限**：store 每个文件最多 2000 行环形缓冲，超出丢头部；后端单次最多 256KB/1000 行，双重防爆；
6. **前端依赖**：需 Node.js ≥ 18（Vite 6）；`npm install` 需联网；`ui/dist` 属于构建产物，加入 `.gitignore`；
7. **静态挂载顺序**：`app.mount("/", ...)` 必须在所有 `/api/*` 路由之后（FastAPI 按注册顺序匹配），否则 API 会被静态文件吞掉；
8. **`document.hidden` 语义**：pywebview 窗口最小化会触发 hidden；开发浏览器里切标签页也触发；「空闲暂停」仅跳过网络请求，timer 仍在跑，切回后立即恢复，无需额外逻辑；
9. **一次轮询两请求**：state 与 logs 并发（`Promise.all` 语义下为顺序 await，可改为并行）——M1 保持简单，两请求串行可接受；若日后想并行，用 `Promise.all([...])` 即可，store 结构无需变动。
